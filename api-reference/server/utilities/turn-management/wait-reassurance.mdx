## Overview

`WaitReassurance` keeps a conversation from going silent while the user waits on background work: once nothing has been said for `interval_secs`, it asks the LLM, in a short developer message, to reassure the user if needed, and the model answers in its own voice or stays silent. What the message means, how to answer it with silence and how to word a reassurance are in the LLM's system instruction, which the processor adds to at start. For the other ways to answer the wait, see [Detecting Idle Users](/pipecat/fundamentals/detecting-user-idle#reassuring-a-waiting-user).

```python
from pipecat.processors.wait_reassurance import WaitReassurance
```

## Configuration

<ParamField path="interval_secs" type="float" default="10.0">
  Seconds the conversation stays quiet, with background work in progress, before
  the LLM is asked whether to say something.
</ParamField>

<ParamField
  path="instruction"
  type="str"
  default="WAIT_REASSURANCE_INSTRUCTION"
>
  The standing guidance added to the LLM's system instruction at start: what the
  message is, how to answer it with silence, and what to say otherwise. A
  template with `{mark}`, the silent mark, so any other brace in it is doubled.
</ParamField>

<ParamField path="prompt" type="str" default="WAIT_REASSURANCE_PROMPT">
  The developer message appended to the conversation each time: the facts of the
  moment and the ask. A template with `{quiet_secs}`, how long nothing has been
  said, and `{mark}` if it wants it. Its opening is what the instruction names
  it by.
</ParamField>

<ParamField path="silent_mark" type="str" default="∅">
  What the model answers with to say nothing. The LLM service honors it once the
  processor announces it at start.
</ParamField>

## Usage

Place the processor after the LLM, a text `LLMService` or an [`LLMWithBackend`](/api-reference/server/composite-services/llm-with-backend):

```python
from pipecat.processors.wait_reassurance import WaitReassurance

pipeline = Pipeline(
    [
        transport.input(),
        stt,
        user_aggregator,
        llm,
        WaitReassurance(),
        tts,
        transport.output(),
        assistant_aggregator,
    ]
)
```

Background work is what a [`BackgroundWorkStartedFrame`](/api-reference/server/frames/system-frames#backgroundworkstartedframe) announced, e.g. an asynchronous function call (`cancel_on_interruption=False`) or a task delegated to an `LLMWithBackend` backend. The model decides what to say with the user's wishes and what it knows of the work in view: "keep me posted in detail" gets the step under way, "just tell me when you're done" gets nothing.

## Frames

### Pushed by

| Frame                                                                                                 | Fields                                                              | Effect                                                                                                                           |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| [`LLMInstructorMetadataFrame`](/api-reference/server/frames/system-frames#llminstructormetadataframe) | `instruction`: the standing guidance, mark filled in; `silent_mark` | Broadcast once, at start. The LLM service composes the instruction into its system instruction and honors the mark from then on. |
| [`LLMMessagesAppendFrame`](/api-reference/server/frames/data-frames#llmmessagesappendframe)           | `messages`: the prompt as a `developer` message; `run_llm=True`     | One per interval of quiet with background work in progress. The assistant aggregator appends it and runs the LLM.                |

## Notes

- **The silent mark is the LLM service's to honor**: A reply that opens with `silent_mark` is dropped by the service itself, which learns the mark from the processor's announcement at start, before the TTS, the context or any observer sees it, and the decision is reported as an [`LLMMarkerResponseFrame`](/api-reference/server/frames/data-frames#llmmarkerresponseframe) of kind `"silent"`, on which the processor starts the interval over.
- **Text LLMs only**: The processor belongs after a text LLM. A speech-to-speech service's audio carries no mark to read.
- **The interval starts over**: A spoken remark starts it over through the bot's speech, and a silent decision starts it over directly, so a long wait gets a fresh decision every `interval_secs`.
- **With `filter_incomplete_user_turns`**: The service reads the mark after its turn-completion filter, so a declined reply of `● ∅` is dropped like one of `∅` alone, and the `●` already pushed for the context is discarded with it.
