## Architecture

The VoicemailDetector is a single frame processor placed after the STT service. It collects transcriptions and asks its classifier whether the call reached a person or a voicemail. After each transcription, the classifier runs in the background and the detector keeps the latest answer. Once the caller has been quiet for `decision_timeout` (default 1 second), the latest answer decides.

The detector holds the bot's speech via a `TTSGate` processor placed after the TTS service. TTS frames are buffered while the decision is pending, then either released (for conversations) or cleared (for voicemail) based on the verdict.

## Performance Considerations

### Classifier Selection

The VoicemailDetector requires a classifier that implements the `BaseClassifier` interface:

**JevClassifier:**

- Fast, specialized classification service
- Recommended for production use
- Requires a Typesafe API key

**LLMClassifier:**

- Uses any LLM service with `run_inference()` support
- Cannot use realtime LLMs (they don't support one-shot inference)
- Has a configurable `timeout` parameter (default 10 seconds)
- Recommended models: OpenAI `gpt-4o`, Google `gemini-2.0-flash`

The main conversation LLM operates independently and can be any type (text-based or realtime).

### Response Timing

The detector has two timing parameters that should be tuned based on your use case:

- `decision_timeout` (default 1.0s): How long to wait after the caller stops speaking before acting on the latest classification
- `voicemail_response_delay` (default 2.0s): How long to wait after a voicemail verdict before leaving the message

## Common Issues

**Classification not working:**

- Confirm both `detector()` and `gate()` are correctly placed in pipeline
- Check that STT service is producing transcriptions
- Verify the classifier is responding (check logs for classification failures)

**Timing problems:**

- Adjust `decision_timeout` if verdicts are too fast or too slow
- Adjust `voicemail_response_delay` based on observed voicemail greeting patterns
- Monitor classification speed with metrics

**Audio playback issues:**

- Ensure `gate()` is placed immediately after TTS service
- Verify TTS frames are being generated before classification completes

## Event Handlers

| Event                      | Description                                |
| -------------------------- | ------------------------------------------ |
| `on_conversation_detected` | Live conversation detected (not voicemail) |
| `on_voicemail_detected`    | Voicemail detected                         |

```python
@voicemail_detector.event_handler("on_conversation_detected")
async def on_conversation_detected(detector):
    print("Live person detected — starting conversation")

@voicemail_detector.event_handler("on_voicemail_detected")
async def on_voicemail_detected(detector):
    print("Voicemail detected — leaving message")
```
