## Overview

`SonioxSTTService` provides real-time speech-to-text transcription using Soniox's WebSocket API with support for over 60 languages, custom context, multiple languages in the same conversation, and advanced features for accurate multilingual transcription.

By default, Soniox uses the `stt-rt-v6` model with `vad_force_turn_endpoint=True`, where Pipecat's user turn strategies decide turn endings and the local VAD finalizes transcripts early. This configuration significantly reduces the time to final segment (~250ms median). Pipecat enables smart-turn detection by default using `LocalSmartTurnAnalyzerV3`. To use Soniox's native turn detection instead, set `vad_force_turn_endpoint=False`.

## Installation

To use Soniox services, install the required dependencies:

```bash
uv add "pipecat-ai[soniox]"
```

## Prerequisites

### Soniox Account Setup

Before using Soniox STT services, you need:

1. **Soniox Account**: Sign up at [Soniox Console](https://console.soniox.com/)
2. **API Key**: Generate an API key from your console dashboard
3. **Language Selection**: Choose from 60+ supported languages and models

### Required Environment Variables

- `SONIOX_API_KEY`: Your Soniox API key for authentication

  Audio format for transcription. Init-only -- not part of runtime-updatable

</ParamField>

<ParamField path="num_channels" type="int" default="1">
  Number of audio channels. Init-only -- not part of runtime-updatable settings.
</ParamField>

<ParamField path="params" type="SonioxInputParams" default="None" deprecated>
  _Deprecated since 0.0.105, removed in 2.0.0._ Use
  `settings=SonioxSTTService.Settings(...)` instead.
</ParamField>

<ParamField path="settings" type="SonioxSTTService.Settings" default="None">
  Runtime-configurable settings for the STT service. See [Settings](#settings)
  below.
</ParamField>

<ParamField path="ttfs_p99_latency" type="float | None" default="0.35">
  P99 latency from speech end to final transcript in seconds. Override for your
  deployment. See [stt-benchmark](https://github.com/pipecat-ai/stt-benchmark).
</ParamField>

<ParamField path="vad_force_turn_endpoint" type="bool" default="True">
  Controls turn detection mode. When `True` (Pipecat mode, default): Pipecat's
  user turn strategies decide turn endings, and a `VADUserStoppedSpeakingFrame`
  sends a finalize message to Soniox. Soniox endpoint detection still ends the
  transcript when the VAD misses speech, but never the turn. When `False`
  (Soniox turn detection mode): Soniox endpoint detection controls turn endings.
  The service proposes a turn start on the local VAD signal when a VAD analyzer
  is configured (most responsive) or on the first transcript token otherwise,
  and proposes a turn stop when the endpoint is detected. The user turn
  strategies resolve those proposals into `UserStartedSpeakingFrame` and
  `UserStoppedSpeakingFrame`.
</ParamField>

<ParamField path="should_interrupt" type="bool" default="True">
  Whether to interrupt the bot when the user starts speaking in Soniox turn
  detection mode (`vad_force_turn_endpoint=False`). Only applies when using
  Soniox's built-in endpoint detection. See [User Turn
  Strategies](/api-reference/server/utilities/turn-management/user-turn-strategies#externaluserturnstrategies)
  if you pass your own `user_turn_strategies`.
</ParamField>

### Settings

Runtime-configurable settings passed via the `settings` constructor argument using `SonioxSTTService.Settings(...)`. These can be updated mid-conversation with `STTUpdateSettingsFrame`. See [Service Settings](/pipecat/fundamentals/service-settings) for details.

| Parameter                           | Type                         | Default       | Description                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------- | ---------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`                             | `str`                        | `"stt-rt-v6"` | Model to use for transcription. _(Inherited from base STT settings.)_                                                                                                                                                                                                                                                                                                                    |
| `language`                          | `Language \| str`            | `None`        | Language for speech recognition. Replaces `language_hints` with this one language, unless the same `Settings` or update also sets `language_hints`. _(Inherited from base STT settings.)_                                                                                                                                                                                                |
| `language_hints`                    | `list[Language]`             | `None`        | Language hints for transcription. Helps the model prioritize expected languages.                                                                                                                                                                                                                                                                                                         |
| `language_hints_strict`             | `bool`                       | `None`        | If true, strictly enforce language hints (only transcribe in provided languages).                                                                                                                                                                                                                                                                                                        |
| `context`                           | `SonioxContextObject \| str` | `None`        | Customization for transcription. Either a `SonioxContextObject` (structured context for steering transcription and translation) or a plain string of background text. Soniox caps the context object at 8k tokens.                                                                                                                                                                       |
| `enable_speaker_diarization`        | `bool`                       | `False`       | Enable speaker diarization. Each contiguous speaker run of a final transcript is pushed as its own frame, with Soniox's speaker label in `speaker.label`. Interim transcripts have no `speaker`. |
| `speaker_format` | `str \| None` | `None` | Format string for diarized speaker runs. Use `{speaker}` for the speaker label, `{speaker_number}` for the speaker's order of first appearance (`1`, `2`, ...), and `{text}` for the transcript text, e.g. `"{speaker}: {text}"`. If `None`, the text is not modified. Updating it at runtime does not reconnect. |
| `enable_language_identification`    | `bool`                       | `False`       | Enable language identification. Tokens are annotated with language IDs, and the detected language is included in the final `TranscriptionFrame`.                                                                                                                                                                                                                                         |
| `max_endpoint_delay_ms`             | `int`                        | `None`        | Maximum delay in milliseconds after speech ends before endpoint detection returns an endpoint. Valid range: 500-3000.                                                                                                                                                                                                                                                                    |
| `endpoint_sensitivity`              | `float`                      | `None`        | Endpoint detection sensitivity (-1.0 to 1.0); higher values finalize turns sooner, lower values delay finalization. Introduced in the v5 model.                                                                                                                                                                                                                                          |
| `endpoint_latency_adjustment_level` | `int`                        | `None`        | Reduces endpoint latency vs. the default (0-3); higher values finalize turns sooner but may reduce accuracy.                                                                                                                                                                                                                                                                             |
| `client_reference_id`               | `str`                        | `None`        | Client reference ID for transcription tracking.                                                                                                                                                                                                                                                                                                                                          |
| `enable_agent_text_input`           | `bool`                       | `True`        | Send each completed bot reply to Soniox as agent text, so words the bot said are recognized when the user repeats them. Only takes effect on `stt-rt-v6` and later models. Agent text is billed as input text tokens.                                                                                                                                                                    |
| `enable_echo_cancellation`          | `bool`                       | `False`       | Send the bot's reply to Soniox word by word while it plays, so Soniox lines the words up with the audio and doesn't transcribe the bot's own voice as the user. Implies `enable_agent_text_input`, replacing the per-reply send. Needs a TTS service that reports word timestamps, such as `SonioxTTSService`; without them the text is sent untimed and echo cancellation doesn't work. |
| `agent_text_lead_ms`                | `int`                        | `700`         | How far ahead of playback each word is sent, in milliseconds. Soniox documents 500-1000; `0` sends each word as it starts playing. Cannot be negative. Only used with `enable_echo_cancellation`.                                                                                                                                                                                        |

## Usage

### Basic Setup

```python
import os

from pipecat.services.soniox.stt import SonioxSTTService

stt = SonioxSTTService(
    api_key=os.getenv("SONIOX_API_KEY"),
)
```

### With Language Hints and Context

```python
from pipecat.services.soniox.stt import SonioxSTTService
from pipecat.transcriptions.language import Language

stt = SonioxSTTService(
    api_key=os.getenv("SONIOX_API_KEY"),
    settings=SonioxSTTService.Settings(
        model="stt-rt-v6",
        language_hints=[Language.EN, Language.ES],
        language_hints_strict=True,
        enable_language_identification=True,
    ),
)
```

### With Context Object (v3+ models)

```python
from pipecat.services.soniox.stt import (
    SonioxSTTService,
    SonioxContextObject,
    SonioxContextGeneralItem,
)

stt = SonioxSTTService(
    api_key=os.getenv("SONIOX_API_KEY"),
    settings=SonioxSTTService.Settings(
        model="stt-rt-v6",
        context=SonioxContextObject(
            general=[
                SonioxContextGeneralItem(key="domain", value="medical"),
            ],
            terms=["Pipecat", "transcription"],
        ),
    ),
)
```

### With Soniox Built-in Turn Detection

Soniox's built-in endpoint detection provides natural turn taking. For the most responsive barge-in, configure a local VAD analyzer so the turn opens on the local VAD signal instead of waiting for the first transcript token:

```python
from pipecat.audio.vad.silero import SileroVADAnalyzer
from pipecat.processors.aggregators.llm_response_universal import (
    LLMContextAggregatorPair,
    LLMUserAggregatorParams,
)
from pipecat.services.soniox.stt import SonioxSTTService
from pipecat.transcriptions.language import Language

stt = SonioxSTTService(
    api_key=os.getenv("SONIOX_API_KEY"),
    vad_force_turn_endpoint=False,  # Use Soniox's built-in endpoint detection
    settings=SonioxSTTService.Settings(
        language_hints=[Language.EN],
        # Optional: Tune endpoint detection timing
        # endpoint_sensitivity=0.3,
        # endpoint_latency_adjustment_level=2,
    ),
)

# Configure user aggregator with VAD for responsive turn opening
user_aggregator, assistant_aggregator = LLMContextAggregatorPair(
    context,
    user_params=LLMUserAggregatorParams(vad_analyzer=SileroVADAnalyzer()),
)
```

## Notes

- **Turn detection modes**:
  - **Pipecat mode** (`vad_force_turn_endpoint=True`, default): a `VADUserStoppedSpeakingFrame` sends a finalize message to Soniox to get the final transcript immediately. This significantly reduces latency. Soniox endpoint detection still ends the transcript when the VAD misses speech, but never the turn. The service emits no turn frames; the user aggregator runs local VAD/smart-turn analysis.
  - **Soniox mode** (`vad_force_turn_endpoint=False`): Soniox endpoint detection is enabled and controls turn endings. The service proposes each turn boundary based on Soniox's detection. The turn opens on the local VAD signal when a VAD analyzer is configured (most responsive) or on the first transcript token otherwise. `should_interrupt` (default `True`) controls barge-in: see [User Turn Strategies](/api-reference/server/utilities/turn-management/user-turn-strategies).
- **Endpoint detection settings**: The `max_endpoint_delay_ms`, `endpoint_sensitivity`, and `endpoint_latency_adjustment_level` settings control Soniox's native endpoint detection, which runs in both modes. When `vad_force_turn_endpoint=True` (the default), the endpoint only ends transcripts, so `max_endpoint_delay_ms` bounds how long the transcript of speech the local VAD missed waits.
- **Keepalive**: The service automatically sends protocol-level keepalive messages to maintain the WebSocket connection.
- **Context**: The `context` setting accepts either a `SonioxContextObject` (structured context that steers transcription and translation) or a plain string of background text. Works on any current Soniox model. Soniox caps the context object at 8k tokens. See the [Soniox context documentation](https://soniox.com/docs/stt/concepts/context) for details.

## Event Handlers

Soniox STT supports the standard [service connection events](/api-reference/server/events/service-events):

| Event             | Description                        |
| ----------------- | ---------------------------------- |
| `on_connected`    | Connected to Soniox WebSocket      |
| `on_disconnected` | Disconnected from Soniox WebSocket |

```python
@stt.event_handler("on_connected")
async def on_connected(service):
    print("Connected to Soniox")
```
