## Overview

`ZoomAIRealtimeLLMService` provides speech-to-speech conversation with the [Voice Agent](https://developers.zoom.us/docs/ai-services/voice-agent/live-mode/) from Zoom AI Services. The Voice Agent runs the whole voice loop on Zoom's side: turn detection, speech recognition, the model, and speech synthesis. The service replaces STT, the LLM, and TTS in a pipeline, and supports function calling, interruptions, and transcripts like [OpenAI Realtime](/api-reference/server/services/s2s/openai). The Voice Agent detects turns and handles barge-in itself, so the pipeline needs no VAD analyzer.

## Installation

```bash
uv add "pipecat-ai[zoom-ai]"
```

## Prerequisites

### Zoom AI Account Setup

1. **Zoom AI Services access**: Sign up through [Zoom AI Services](https://www.zoom.ai/).
2. **API key**: Create a Zoom AI Services API key. See [Get credentials](https://developers.zoom.us/docs/ai-services/auth/).

### Required Environment Variables

- `ZOOM_AI_API_KEY`: Your Zoom AI Services API key

### Settings

Runtime-configurable settings passed via the `settings` constructor argument using `ZoomAIRealtimeLLMService.Settings(...)`. They map to the Voice Agent's [session settings](https://developers.zoom.us/docs/ai-services/voice-agent/live-mode/#configure-the-session) and can be updated mid-conversation with `LLMUpdateSettingsFrame`. See [Service Settings](/pipecat/fundamentals/service-settings) for details.

| Parameter            | Type                | Default               | Description                                                                                                                                                                                                                                                                         |
| -------------------- | ------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`              | `str`               | `"gemma-4"`           | Model identifier: a Zoom model, or your `provider`'s model when the provider sets none of its own. Fixed once the session is configured. See [Think settings](https://developers.zoom.us/docs/ai-services/voice-agent/live-mode/#think-settings). _(Inherited from base settings.)_ |
| `system_instruction` | `str \| None`       | `None`                | System instruction/prompt. _(Inherited from base settings.)_                                                                                                                                                                                                                        |
| `session_properties` | `SessionProperties` | `SessionProperties()` | OpenAI Realtime session properties. The service uses `instructions`, `tools`, `tool_choice`, `max_output_tokens`, `reasoning`, and `audio.output.voice` (when `speak` sets no voice).                                                                                               |
| `provider`           | `Provider \| None`  | `None`                | Where the model runs: Zoom's own models (`None`), or your own OpenAI or Anthropic account. Fixed once the session is configured. See [Provider](#provider).                                                                                                                         |
| `listen`             | `Listen \| None`    | `None`                | How the agent listens: the caller's language and custom vocabulary. `None` takes the server's defaults. Fixed once the session is configured. See [Listen](#listen).                                                                                                                |
| `speak`              | `Speak \| None`     | `None`                | How the agent speaks: its voice. `None` takes the server's default voice. See [Speak](#speak).                                                                                                                                                                                      |
| `extra`              | `dict[str, Any]`    | `{}`                  | Voice Agent session fields the service has no setting for, shaped like the `session` of `session.update`. Merged into each session update over the settings above.                                                                                                                  |

`provider`, `listen`, and `speak` also accept plain dicts in the same shape, such as `{"voice": "ava"}`.

## Usage

### Basic Setup

```python
import os
from pipecat.services.zoom_ai.realtime.llm import ZoomAIRealtimeLLMService

llm = ZoomAIRealtimeLLMService(
    api_key=os.getenv("ZOOM_AI_API_KEY"),
    settings=ZoomAIRealtimeLLMService.Settings(
        system_instruction="You are a helpful assistant.",
    ),
)
```

Register tools on the `LLMContext`, as for other LLM services. See [Function Calling](/pipecat/learn/function-calling).

### With Voice and Vocabulary

```python
from pipecat.services.zoom_ai.realtime.events import (
    Listen,
    Speak,
    Transcription,
    Vocabulary,
)

llm = ZoomAIRealtimeLLMService(
    api_key=os.getenv("ZOOM_AI_API_KEY"),
    settings=ZoomAIRealtimeLLMService.Settings(
        system_instruction="You are a helpful assistant.",
        speak=Speak(voice="jenna"),
        listen=Listen(
            transcription=Transcription(
                language="en",
                vocabulary=Vocabulary(phrases=["Pipecat"]),
            )
        ),
    ),
)
```

### With Your Own Model Provider

```python
from pipecat.services.zoom_ai.realtime.events import Provider

llm = ZoomAIRealtimeLLMService(
    api_key=os.getenv("ZOOM_AI_API_KEY"),
    settings=ZoomAIRealtimeLLMService.Settings(
        model="gpt-4o",
        provider=Provider(
            type="openai",
            headers={"X-Api-Key": os.getenv("OPENAI_API_KEY")},
        ),
    ),
)
```

The Voice Agent still transcribes the caller and speaks the reply; only the model's turn uses your provider account.

### Updating Settings Mid-Conversation

Send an `LLMUpdateSettingsFrame` to change the instructions, tools, or voice during a conversation:

```python
from pipecat.frames.frames import LLMUpdateSettingsFrame
from pipecat.services.zoom_ai.realtime.events import Speak

await worker.queue_frame(
    LLMUpdateSettingsFrame(
        delta=ZoomAIRealtimeLLMService.Settings(
            system_instruction="You are now a shipping assistant.",
            speak=Speak(voice="ava"),
        )
    )
)
```

## Notes

- **Turn detection**: The Voice Agent detects turns, noise, and barge-in itself. None of these is configurable.
- **Settings fixed at connection**: `model`, `provider`, and `listen` are fixed once the session is configured. Updating them mid-conversation logs a warning and applies to the next session. Updates to instructions, tools, and voice take effect immediately.
- **Audio**: Input audio is sent at the pipeline's input sample rate. The agent speaks 16 kHz audio, played at 24 kHz. Audio that arrives while the session is connecting or reconnecting is held (up to the latest three seconds) and sent once the session is ready.
- **Transcripts**: The caller's speech is pushed upstream as `TranscriptionFrame`s, and the agent's speech downstream as `TTSTextFrame`s.
- **Text-only replies**: When the audio output modality is disabled, the agent replies in text only.
- **Reconnection**: A session lasts up to 60 minutes. If the session ends unexpectedly (the connection closing, or a session reaching its time limit), the service reconnects, up to 3 times in a row, and restores the conversation. If reconnecting fails, it pushes a permanent error.
- **Errors**: If Zoom refuses the connection (an invalid API key, for example), the error includes Zoom's reason. Errors the Voice Agent reports without ending the session are pushed as non-fatal errors. If it rejects the session's settings (an unknown voice, say) or the provider rejects your provider key, the error is permanent. Errors from the Voice Agent include the session's tracking ID (`x-zm-trackingid`), which Zoom support uses to find a session. See [Error Handling](/pipecat/fundamentals/error-handling).
- **Function call output**: A function call's output is created right after the call in the conversation, where the Voice Agent's model reads it.
- **System instruction precedence**: The `system_instruction` from service settings takes precedence over an initial system message in the LLM context. A warning is logged when both are set.

## Event Handlers

| Event                          | Description                                                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `on_conversation_item_created` | Called when a new conversation item is created in the session                                                        |
| `on_conversation_item_updated` | Called when a conversation item is updated or completed. `item` is `None` when a user audio transcription completes. |

```python
@llm.event_handler("on_conversation_item_created")
async def on_item_created(service, item_id, item):
    print(f"New conversation item: {item_id}")

@llm.event_handler("on_conversation_item_updated")
async def on_item_updated(service, item_id, item):
    print(f"Conversation item updated: {item_id}")
```
