## Overview

`DailyTransport` provides real-time audio and video communication using Daily's hosted WebRTC platform. It handles bidirectional media streams, participant management, transcription, recording, and telephony features without requiring your own WebRTC infrastructure. Daily manages all the complexity of WebRTC connections, NAT traversal, and global media routing.

## Installation

To use `DailyTransport`, install the required dependencies:

```bash
uv add "pipecat-ai[daily]"
```

## Prerequisites

### Daily Account Setup

Before using DailyTransport, you need:

1. **Daily Account**: Sign up at [Daily Dashboard](https://dashboard.daily.co/u/signup?pipecat=true)
2. **API Key**: Generate a Daily API key from your dashboard
3. **Room Creation**: Daily rooms must be created before connecting (see Usage section)

### Required Environment Variables

- `DAILY_API_KEY`: Your Daily API key for room creation and management

## Key Features

- **Hosted WebRTC**: No infrastructure setup required - Daily handles all WebRTC complexity
- **Multi-participant Support**: Handle multiple participants with individual audio/video tracks
- **Multi-track Audio/Video**: Publish multiple custom audio and video tracks simultaneously with per-track configuration, including built-in support for Daily's `screenAudio` and `screenVideo` destinations
- **Built-in Transcription**: Real-time speech-to-text with Deepgram integration
- **Telephony Integration**: Dial-in/dial-out support for phone numbers via [SIP](/pipecat/telephony/twilio-daily-sip)/[PSTN](/pipecat/telephony/daily-pstn)
- **Recording & Streaming**: Built-in call recording and live streaming capabilities
- **Global Infrastructure**: Daily's edge network ensures low latency worldwide
- **Advanced Controls**: Participant management, permissions, and media routing

## Usage

DailyTransport connects your Pipecat bot to Daily rooms where it can communicate with participants through audio, video, and data channels. Rooms must be created using the Daily API before your bot can join.

The transport integrates with Pipecat's pipeline to process participant audio through your STT, LLM, and TTS services, then send responses back to participants.

See the [complete example](https://github.com/pipecat-ai/pipecat/blob/main/examples/transports/transports-daily.py) for a full implementation including:

- Daily room creation and token management
- Transport configuration with transcription and VAD
- Pipeline integration with participant event handling
- Advanced features like recording and dial-out

## Frames

**Sent to the transport:**

| Frame                                    | Fields                                                 | Effect                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DailySIPTransferFrame`                  | `settings`                                             | Transfers the phone or SIP call to `settings["toEndPoint"]`, a phone number or SIP URI, once the audio queued before it has played. Without a `sessionId` in `settings`, it transfers the dial-out session, else the dial-in session.                                                                                          |
| `DailySIPReferFrame`                     | `settings`                                             | Sends a SIP REFER for the call to `settings["toEndPoint"]`, once the audio queued before it has played. Without a `sessionId` in `settings`, it refers the dial-out session, else the dial-in session, and with neither it fails with an error.                                                                                |
| `DailyUpdateRemoteParticipantsFrame`     | `remote_participants`                                  | Applies Daily's [remote participant updates](https://reference-python.daily.co/api_reference.html#daily.CallClient.update_remote_participants), such as permissions, once the audio queued before it has played.                                                                                                               |
| `DailyOutputDTMFFrame`                   | `buttons`, `session_id`, `digit_duration_ms`, `method` | Sends DTMF tones once the audio queued before it has played. Without `session_id`, it sends to the dial-out session, else the dial-in session, and with neither it sends nothing and pushes an `ErrorFrame`. `None` for `digit_duration_ms` or `method` (`"telephone-event"`, `"sip-info"`, or `"auto"`) uses Daily's default. |
| `DailyOutputDTMFUrgentFrame`             | `buttons`, `session_id`, `digit_duration_ms`, `method` | Sends DTMF tones at once, as `DailyOutputDTMFFrame` does.                                                                                                                                                                                                                                                                      |
| `DailyOutputTransportMessageFrame`       | `message`, `participant_id`                            | Sends an app message to `participant_id`, or to everyone when it is `None`, once the audio queued before it has played.                                                                                                                                                                                                        |
| `DailyOutputTransportMessageUrgentFrame` | `message`, `participant_id`                            | Sends an app message at once, as `DailyOutputTransportMessageFrame` does.                                                                                                                                                                                                                                                      |

When Daily rejects a transfer, REFER, or participant update, the transport pushes an `ErrorFrame`. [`OutputDTMFFrame`](/api-reference/server/frames/data-frames#outputdtmfframe) and [`OutputDTMFUrgentFrame`](/api-reference/server/frames/system-frames#outputdtmfurgentframe) also go over Daily's DTMF channel rather than as audio tones, to the dial-out session, else the dial-in session.

**Pushed by the transport:**

| Frame                             | Fields                      | Meaning                                                                                                                                                                                                |
| --------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DailyInputTransportMessageFrame` | `message`, `participant_id` | An app message from participant `participant_id`, pushed both upstream and downstream. It is an [`InputTransportMessageFrame`](/api-reference/server/frames/system-frames#inputtransportmessageframe). |

Queue a goodbye and a transfer together, and the transfer waits for the goodbye to finish playing:

```python
from pipecat.frames.frames import TTSSpeakFrame
from pipecat.transports.daily.transport import DailySIPTransferFrame

goodbye = TTSSpeakFrame("Transferring you to our billing team now.")
transfer = DailySIPTransferFrame(settings={"toEndPoint": "+15551234567"})
# Otherwise the caller talking over the goodbye drops the transfer
goodbye.interruptible = False
transfer.interruptible = False

await worker.queue_frames([goodbye, transfer])
```

For a transfer the LLM decides on, see [Implementing a cold transfer](/pipecat/telephony/daily-pstn#implementing-a-cold-transfer).

## Methods

### capture_participant_transcription()

```python
async def capture_participant_transcription(participant_id: str)
```

Requests Daily's built-in transcription for a participant. Does nothing unless `transcription_enabled` is set; see [Using built-in transcription](#using-built-in-transcription).

### capture_participant_audio()

```python
async def capture_participant_audio(
    participant_id: str,
    audio_source: str = "microphone",
    sample_rate: int = 16000,
)
```

Captures one of a participant's audio sources (`"microphone"`, `"screenAudio"`, or a custom track name) and pushes it as `UserAudioRawFrame`s with `user_id` set to the participant and `transport_source` set to `audio_source`. With `audio_in_user_tracks=True`, the default, each participant's microphone is captured as they join, so call this for other sources. Requires `audio_in_enabled=True` and `transport.input()` in the pipeline.

### capture_participant_video()

```python
async def capture_participant_video(
    participant_id: str,
    framerate: int | None = 30,
    video_source: str = "camera",
    color_format: str = "RGB",
    *,
    on_request_only: bool = False,
)
```

Captures one of a participant's video sources and pushes its frames as `UserImageRawFrame`s in `color_format`. The other arguments work as in [Capturing video on demand](/api-reference/server/services/transport/transport-params#capturing-video-on-demand). Requires `video_in_enabled=True` and `transport.input()` in the pipeline.

### start_dialout()

```python
async def start_dialout(
    settings: Mapping[str, Any] | None = None,
) -> tuple[str, str | None]
```

Dials out from the room and returns `(session_id, error)`, where `error` is `None` on success. `settings` takes Daily's [dial-out settings](https://reference-python.daily.co/api_reference.html#daily.CallClient.start_dialout), such as `phoneNumber` or `sipUri`. The room needs dial-out enabled; see [Daily PSTN](/pipecat/telephony/daily-pstn#dial-out) and [Daily SIP](/pipecat/telephony/daily-sip#dial-out).

### stop_dialout()

```python
async def stop_dialout(participant_id: str) -> str | None
```

Hangs up the dial-out call to a participant and returns an error description, or `None` on success.

### start_recording()

```python
async def start_recording(
    streaming_settings: Mapping[str, Any] | None = None,
    stream_id: str | None = None,
    force_new: bool | None = None,
) -> tuple[str, str | None]
```

Starts Daily's cloud recording and returns `(stream_id, error)`, where `error` is `None` on success. Cloud recording must be enabled on the room or token via `enable_recording`; see [DailyRESTHelper](/api-reference/server/utilities/daily/rest-helper). The recording events are under [Recording](#recording).

```python
@transport.event_handler("on_first_participant_joined")
async def on_first_participant_joined(transport, participant):
    stream_id, error = await transport.start_recording()
    if error:
        logger.error(f"Failed to start recording: {error}")
```

To record from the moment the bot joins instead, configure the meeting token with `DailyRESTHelper`:

```python
from pipecat.transports.daily.utils import (
    DailyMeetingTokenParams,
    DailyMeetingTokenProperties,
)

token = await helper.get_token(
    room_url="https://your-domain.daily.co/my-room",
    params=DailyMeetingTokenParams(
        properties=DailyMeetingTokenProperties(
            enable_recording="cloud",
            start_cloud_recording=True,
        )
    ),
)
```

### stop_recording()

```python
async def stop_recording(stream_id: str | None = None) -> str | None
```

Stops a cloud recording and returns an error description, or `None` on success.

### update_publishing()

```python
async def update_publishing(publishing_settings: Mapping[str, Any]) -> str | None
```

Updates the bot's [publishing settings](https://reference-python.daily.co/types.html#publishingsettings), such as camera encodings, and returns an error description, or `None` on success.

### participants()

```python
def participants() -> Mapping[str, Any]
```

Returns the participants in the room as Daily reports them, keyed by participant ID, with the bot under the key `"local"`.

## Notes

### Using built-in transcription

Daily can transcribe the call for you (powered by Deepgram) instead of you adding a dedicated STT service to the pipeline. Set `transcription_enabled=True` on `DailyParams`:

```python
from pipecat.transports.daily.transport import (
    DailyTransport,
    DailyParams,
    DailyTranscriptionSettings,
)

transport = DailyTransport(
    room_url,
    token,
    "Voice Bot",
    DailyParams(
        audio_in_enabled=True,
        audio_out_enabled=True,
        transcription_enabled=True,
        transcription_settings=DailyTranscriptionSettings(
            language="en",
            model="nova-3-general",
        ),
    ),
)
```

With this enabled, Daily runs transcription server-side and the transport pushes `TranscriptionFrame`s into the pipeline. **You do not add a separate STT service** (no `DeepgramSTTService`, etc.) — the transport fills that role. Your bot receives the same transcriptions in-call participants see, and you can also handle them directly via the [`on_transcription_message`](#on_transcription_message) event.

The transport requests transcription only for participants passed to `capture_participant_transcription()`, so call it for each participant you want transcribed:

```python
@transport.event_handler("on_first_participant_joined")
async def on_first_participant_joined(transport, participant):
    await transport.capture_participant_transcription(participant["id"])
```

When to use this versus a dedicated STT service:

- **Built-in (`transcription_enabled=True`)**: one less service to wire up. Billed by Daily per participant-minute, separate from your own Deepgram key. Less control over provider and tuning.
- **Dedicated STT service in the pipeline**: full control over provider, model, and settings, billed on your own provider account. This is what most Pipecat examples use. See [Speech to Text](/pipecat/learn/speech-to-text).

<Warning>
  Only enable one STT service. Enabling `transcription_enabled` **and** adding
  an STT processor will transcribe the same audio twice and bill you twice.
</Warning>

### Screen Audio Destination

DailyTransport includes built-in support for Daily's `screenAudio` destination. When `"screenAudio"` is included in the `audio_out_destinations` parameter, a dedicated screen audio track is automatically created when the transport starts:

```python
params = DailyParams(
    audio_out_enabled=True,
    audio_out_destinations=["screenAudio"]
)

# Route frames to the screen audio track
frame = OutputAudioRawFrame(...)
frame.transport_destination = "screenAudio"
```

Optionally configure the `screenAudio` track with custom parameters:

```python
params = DailyParams(
    audio_out_enabled=True,
    audio_out_destinations=["screenAudio"],
    custom_audio_track_params={
        "screenAudio": DailyCustomAudioTrackParams(
            sample_rate=48000,
            channels=2,
            send_settings={"maxBitrate": 128000}
        )
    }
)
```

### Screen Video Destination

DailyTransport includes built-in support for Daily's `screenVideo` destination. When `"screenVideo"` is included in the `video_out_destinations` parameter, a dedicated screen video track is automatically created when the transport starts:

```python
params = DailyParams(
    video_out_enabled=True,
    video_out_is_live=True,
    video_out_width=1280,
    video_out_height=720,
    video_out_destinations=["screenVideo"]
)

# Route frames to the screen video track
frame = OutputImageRawFrame(...)
frame.transport_destination = "screenVideo"
```

### Camera Publishing Settings

The `camera_out_send_settings` parameter provides full control over the camera track's publishing configuration:

```python
params = DailyParams(
    camera_out_send_settings={
        "maxQuality": "high",
        "encodings": {
            "high": {"maxBitrate": 2_000_000, "maxFramerate": 30}
        },
    },
)
```

<Warning>
  The `TransportParams.video_out_bitrate` parameter is deprecated for Daily. Use
  `DailyParams.camera_out_send_settings` instead to configure camera publishing
  encodings (bitrate, framerate, codec, etc.).
</Warning>

### Room Lifecycle

#### on_joined

Fired when the bot successfully joins the Daily room.

```python
@transport.event_handler("on_joined")
async def on_joined(transport, data):
    print(f"Bot joined the room: {data}")
```

**Parameters:**

| Parameter   | Type             | Description                |
| ----------- | ---------------- | -------------------------- |
| `transport` | `DailyTransport` | The transport instance     |
| `data`      | `dict`           | Join event data from Daily |

#### on_connected

Fired when the bot connects to the Daily room. This is an alias for `on_joined` that provides a consistent event name across all transport types.

```python
@transport.event_handler("on_connected")
async def on_connected(transport, data):
    print(f"Bot connected to the room: {data}")
```

**Parameters:**

| Parameter   | Type             | Description                |
| ----------- | ---------------- | -------------------------- |
| `transport` | `DailyTransport` | The transport instance     |
| `data`      | `dict`           | Join event data from Daily |

#### on_left

Fired when the bot leaves the Daily room.

```python
@transport.event_handler("on_left")
async def on_left(transport):
    print("Bot left the room")
```

**Parameters:**

| Parameter   | Type             | Description            |
| ----------- | ---------------- | ---------------------- |
| `transport` | `DailyTransport` | The transport instance |

#### on_before_leave

Fired synchronously just before the bot leaves the room. Use this for cleanup that must happen before disconnection, such as stopping transcription.

```python
@transport.event_handler("on_before_leave")
async def on_before_leave(transport):
    print("About to leave the room...")
```

**Parameters:**

| Parameter   | Type             | Description            |
| ----------- | ---------------- | ---------------------- |
| `transport` | `DailyTransport` | The transport instance |

<Note>
  This is a **synchronous** event — the bot will not leave the room until all
  handlers complete. Keep handlers fast.
</Note>

#### on_error

Fired when a transport-level error occurs.

It also fires once when the call ends without `leave()` (the bot is ejected, or the room or meeting ends). The transport then drops app messages until it joins again.

```python
@transport.event_handler("on_error")
async def on_error(transport, error):
    print(f"Transport error: {error}")
```

**Parameters:**

| Parameter   | Type             | Description            |
| ----------- | ---------------- | ---------------------- |
| `transport` | `DailyTransport` | The transport instance |
| `error`     | `str`            | Error message          |

#### on_call_state_updated

Fired when the call state changes (e.g., joining, joined, leaving, left).

```python
@transport.event_handler("on_call_state_updated")
async def on_call_state_updated(transport, state):
    print(f"Call state: {state}")
```

**Parameters:**

| Parameter   | Type             | Description            |
| ----------- | ---------------- | ---------------------- |
| `transport` | `DailyTransport` | The transport instance |
| `state`     | `str`            | The new call state     |

#### on_network_connection_status_updated

Fired when a network connection needed for the call is interrupted or connects.

While the `"signalling"` connection is interrupted, the transport logs a warning and drops app messages until it reconnects. A failed app message is reported once as an error until a send succeeds.

```python
@transport.event_handler("on_network_connection_status_updated")
async def on_network_connection_status_updated(transport, status):
    print(f"{status['connection']}: {status['event']}")
```

**Parameters:**

| Parameter   | Type             | Description                                                                                                  |
| ----------- | ---------------- | ------------------------------------------------------------------------------------------------------------ |
| `transport` | `DailyTransport` | The transport instance                                                                                       |
| `status`    | `dict`           | `connection` (`"signalling"`, `"sendTransport"`, or `"recvTransport"`) and `event` (`"connected"` or `"interrupted"`) |

### Telephony: DTMF

#### on_dtmf_event

Fired when a DTMF (dual-tone multi-frequency) keypad tone is received from a phone caller. The transport automatically pushes an `InputDTMFFrame` into the pipeline, enabling your bot to react to keypad presses.

```python
@transport.event_handler("on_dtmf_event")
async def on_dtmf_event(transport, data):
    tone = data["tone"]
    print(f"Received DTMF tone: {tone}")
```

**Parameters:**

| Parameter   | Type             | Description                                           |
| ----------- | ---------------- | ----------------------------------------------------- |
| `transport` | `DailyTransport` | The transport instance                                |
| `data`      | `dict`           | DTMF event data from Daily containing `tone` (string) |

<Note>
  DTMF tones are automatically converted to `InputDTMFFrame` and pushed into the
  pipeline. You can handle these frames in your processors to implement IVR
  menus or other telephony interactions.
</Note>
