## Overview

`SIPTransport` makes a pipeline a SIP endpoint. The bot registers a SIP account (or dials through a registration-less trunk), answers inbound calls, places outbound calls, and exchanges audio, video, and DTMF with the pipeline. Its events and call-control methods use the same names as the dial-in and dial-out surface of [`DailyTransport`](/api-reference/server/services/transport/daily), so a bot can switch between the two by changing the constructor and params.

Each `SIPTransport` handles one call. Create several instances, each with its own `SIPConnection`, to hold several conversations on one account.

## Installation

```bash
uv add "pipecat-ai[sip]"
```

## Prerequisites

A SIP account to register with, or a Daily domain to provision one on. With the [development runner](/api-reference/server/utilities/runner/guide#sip-transport-sip), a bot with no configured account gets a temporary Daily SIP client (`DAILY_API_KEY`). See [`DailyRESTHelper`](/api-reference/server/utilities/daily/rest-helper) to create SIP clients yourself.

## Configuration

```python
from pipecat.transports.sip.connection import SIPConnection
from pipecat.transports.sip.transport import SIPParams, SIPTransport
```

### SIPParams

`SIPParams` extends `TransportParams`; the fields below are the ones it adds or overrides.

| Parameter               | Type          | Default | Description                                                                                                                                                                                 |
| ----------------------- | ------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto_answer`           | `bool`        | `True`  | Answer inbound calls as they arrive, accepting video when a video direction is enabled. When `False`, the call keeps ringing until you call `connection.answer()` or `connection.reject()`. |
| `trunk`                 | `str \| None` | `None`  | Domain (or `host:port`) that turns a `phoneNumber` dial-out into `sip:+E164@trunk`. Without it, dial-out requires a full `sipUri`.                                                          |
| `audio_out_10ms_chunks` | `int`         | `2`     | Number of 10 ms chunks per outbound audio buffer. The default sends 20 ms buffers, matching typical RTP packet time.                                                                        |

### SIPConnection

All parameters are keyword-only. Parameters marked runtime-wide are shared by every `SIPConnection` in the process, and a connection that disagrees with the running settings raises `ValueError`. Connections that share a `user` and `domain` must agree on `transport`, `registrar`, `password`, `auth_user`, `audio_codecs`, `dtmf_mode`, and `extra_params`.

<ParamField path="user" type="str" required>
  The user part of `sip:user@domain`.
</ParamField>

<ParamField path="domain" type="str" required>
  Registration domain. May carry a port.
</ParamField>

<ParamField path="password" type="str" default='""'>
  Authentication password. May be empty.
</ParamField>

<ParamField path="auth_user" type="str | None" default="None">
  Digest username, when the credential store keys it differently from `user`
  (credential-list trunks).
</ParamField>

<ParamField path="transport" type="str" default='"udp"'>
  SIP transport: `"udp"`, `"tcp"`, or `"tls"`.
</ParamField>

<ParamField path="registrar" type="str | None" default="None">
  Outbound proxy to register through, when it is not the domain itself.
</ParamField>

<ParamField path="reg_interval" type="int" default="600">
  Seconds between registration refreshes. `0` disables registration (trunk
  mode): the connection never sends REGISTER and dials targets directly. Without
  a registration, a SIP server cannot route inbound calls to the bot, so dial-in
  works only when the peer reaches the bot's listening socket directly, and
  `on_dialin_ready` never fires.
</ParamField>

<ParamField path="audio_codecs" type="tuple | None" default="None">
  Codec preference order by stack name, for example `("opus/48000/2",
  "PCMU/8000/1")`. `None` uses the stack default.
</ParamField>

<ParamField path="dtmf_mode" type="str" default='"rtpevent"'>
  How DTMF is sent: `"rtpevent"`, `"info"`, or `"auto"`.
</ParamField>

<ParamField path="extra_params" type="tuple | None" default="None">
  Raw baresip account parameters, each a `"key=value"` string appended verbatim
  to the SIP address-of-record, for account directives Pipecat does not model.
  For media-NAT traversal, `("medianat=stun", "stunserver=stun:HOST:PORT")`
  advertises the address a STUN server reports, which reaches the bot through an
  endpoint-independent NAT. Behind a symmetric NAT (such as an AWS NAT Gateway)
  that address is unreachable: the call needs a peer that latches onto the bot's
  RTP source address, or `medianat=turn` with a TURN server.
</ParamField>

<ParamField path="jitter_buffer_mode" type="str | None" default="None">
  Receive jitter buffer: `"off"`, `"fixed"`, or `"adaptive"`. With no mode and
  no `jitter_buffer_ms`, the buffer is fixed at 40-60 ms. The buffer holds media
  before the transport reads it, so its size adds to turn latency. A fixed
  buffer costs its minimum on every packet; an adaptive buffer widens under
  jitter and does not narrow again for the rest of the call. A packet arriving
  later than the minimum plus one packet time is discarded. Runtime-wide.
</ParamField>

<ParamField path="jitter_buffer_ms" type="tuple | None" default="None">
  `(min, max)` in milliseconds for a fixed or adaptive buffer. Given alone, it
  selects `"fixed"`. Not accepted with `"off"`. Runtime-wide.
</ParamField>

<ParamField path="net_interface" type="str | None" default="None">
  Restrict the stack to one local interface, by name or address, for example
  `"127.0.0.1"` for a registrar on loopback or one address of a multi-homed
  host. `None` lets the OS pick the source address per destination.
  Runtime-wide.
</ParamField>

<ParamField path="expose_headers" type="tuple" default="()">
  SIP header names whose values are included in call events. Runtime-wide.
</ParamField>

<ParamField path="max_concurrent_calls" type="int | None" default="2">
  Simultaneous-call cap for the process; further inbound INVITEs are refused
  with 486. `None` means unlimited. Runtime-wide.
</ParamField>

<ParamField path="rtp_timeout" type="int" default="0">
  Seconds without received RTP after which a call is closed with reason `"rtp
  stream error"`. Held and send-only streams are not checked. `0` disables
  detection. Runtime-wide.
</ParamField>

<ParamField path="instance_id" type="str | None" default="None">
  A canonical lowercase UUID identifying this endpoint across restarts (RFC 5626
  `+sip.instance`), so a supporting registrar replaces a restarted bot's stale
  registration. `None` sends no instance parameter. Runtime-wide.
</ParamField>

<ParamField path="video_size" type="tuple" default="(640, 480)">
  Video width and height for both directions. Runtime-wide.
</ParamField>

<ParamField path="video_fps" type="float" default="30.0">
  Transmit frame rate. Runtime-wide.
</ParamField>

<ParamField path="video_bitrate" type="int" default="1000000">
  VP8 encoder target in bits per second. Runtime-wide.
</ParamField>

<ParamField path="native_log_level" type="str" default='"warning"'>
  Lowest severity captured from the native SIP stack's logging: `"debug"`,
  `"info"`, `"warning"`, or `"error"`. Records appear in Pipecat's log output.
  Runtime-wide.
</ParamField>

<ParamField path="sip_trace" type="bool" default="False">
  Log every SIP message sent and received, verbatim. The trace contains call
  metadata and digest authentication material, so leave it off in production.
  Runtime-wide.
</ParamField>

<ParamField path="route_inbound" type="bool" default="True">
  Whether inbound calls on the account are routed to this connection. Set it to
  `False` for a connection that only places calls.
</ParamField>

## Usage

### Dial-in

```python
connection = SIPConnection(user="1001", domain="sip.example.com", password="...")
transport = SIPTransport(
    connection,
    SIPParams(audio_in_enabled=True, audio_out_enabled=True),
)

@transport.event_handler("on_dialin_ready")
async def on_dialin_ready(transport, aor):
    print(f"Registered as {aor}")

@transport.event_handler("on_client_connected")
async def on_client_connected(transport, participant):
    ...
```

### Dial-out

```python
@transport.event_handler("on_connected")
async def on_connected(transport, data=None):
    session_id, error = await transport.start_dialout({"sipUri": "sip:1002@sip.example.com"})
    if error:
        print(error)
```

### Creating the transport with the runner

Under the development runner, or on Pipecat Cloud, `create_transport()` builds the connection from the runner arguments, so the bot code is the same everywhere:

```python
from pipecat.runner.utils import create_transport

transport_params = {
    "sip": lambda: SIPParams(audio_in_enabled=True, audio_out_enabled=True),
}

async def bot(runner_args):
    transport = await create_transport(runner_args, transport_params)
```

### Video

Calls made or answered with a video direction enabled carry VP8 video. Video crosses the pipeline as RGB `InputImageRawFrame` and `OutputImageRawFrame`. With `video_out_enabled`, the transport sets the call's video size and frame rate from `video_out_width`, `video_out_height`, and `video_out_framerate`. A peer that declines video leaves a working audio call.

## Methods

All call-control methods return an error description as a `str`, or `None` on success. They do not raise.

### start_dialout

```python
await transport.start_dialout(settings=None) -> tuple[str, str | None]
```

Places a call and returns `(session_id, error)`. `settings` takes:

| Key           | Description                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `sipUri`      | Direct SIP target.                                                                                                                   |
| `phoneNumber` | Phone number, used with `SIPParams.trunk`.                                                                                           |
| `video`       | `True` offers send and receive video. A direction string offers that direction; `"inactive"` negotiates video without activating it. |
| `headers`     | Dict of extra INVITE headers.                                                                                                        |

Returns an error when the transport already has an active call.

### stop_dialout

```python
await transport.stop_dialout(participant_id) -> str | None
```

Hangs up the dial-out call whose session id is `participant_id`.

### send_dtmf

```python
await transport.send_dtmf(settings) -> str | None
```

Sends DTMF tones on the active call. `settings` takes `tones` (the digits), and optionally `sessionId` and `method` (`"telephone-event"` or `"sip-info"`). The wire method is set by the connection's `dtmf_mode`; a `method` that does not match it returns an error.

### sip_refer

```python
await transport.sip_refer(settings) -> str | None
```

Sends a SIP REFER that asks the caller to call `settings["toEndPoint"]` (blind transfer). On success the call closes. Takes an optional `sessionId`.

### sip_attended_transfer

```python
await transport.sip_attended_transfer(settings) -> str | None
```

Dials `settings["toEndPoint"]` on a consult leg, waits for it to answer, then sends a REFER with a Replaces header so the two peers connect directly. Both of the bot's legs close, and the active call's close is reported with reason `"transferred"`. If the transfer fails, the original call resumes. Takes an optional `sessionId`.

`sip_refer()` and `sip_attended_transfer()` need a peer that processes REFER, such as a SIP PBX or registrar (FreeSWITCH, Asterisk, Kamailio), not a carrier PSTN trunk.

### sip_call_transfer

```python
await transport.sip_call_transfer(settings) -> str | None
```

Always returns an error; Daily's cloud-mediated transfer has no SIP equivalent. Use `sip_refer()` or `sip_attended_transfer()`.

### Video control

```python
await transport.set_video_direction(direction) -> str | None
await transport.add_video() -> str | None
await transport.remove_video() -> str | None
await transport.request_keyframe() -> None
```

`set_video_direction()` renegotiates the call's video with `"sendrecv"`, `"sendonly"`, `"recvonly"`, or `"inactive"`; the call must already carry a video stream. `add_video()` and `remove_video()` set `"sendrecv"` and `"inactive"`. `request_keyframe()` asks the far end for a video keyframe.

## Notes

- **Transfers**: A transfer that succeeds closes the bot's side of the call. `sip_call_transfer` is not supported.
- **Trunk mode**: `reg_interval=0` is independent of `SIPParams.trunk`, which only builds `sip:+E164@trunk` URIs from `phoneNumber`. PSTN trunking typically uses both. Treat `on_connected` as the ready signal, since `on_dialin_ready` does not fire.
- **DTMF**: Received digits that are not keypad entries (`A`-`D`) fire `on_dtmf_event` but produce no `InputDTMFFrame`.
- **Differences from DailyTransport**: `on_connected` carries no payload, so cross-transport handlers should accept `data=None`. Dial-out has no per-call `callerId`, `codecs`, or `videoSettings`; use the connection's `user`, `audio_codecs`, and `video_size`. Rooms, `on_app_message`, transcription, and recording events do not exist on this transport.

## Event Handlers

| Event                         | Arguments                        | Description                                                                  |
| ----------------------------- | -------------------------------- | ---------------------------------------------------------------------------- |
| `on_connected`                | `transport`                      | The connection is up.                                                        |
| `on_left`                     | `transport`                      | The connection closed.                                                       |
| `on_before_leave`             | `transport`                      | About to leave. Synchronous.                                                 |
| `on_error`                    | `transport, error`               | A transport error occurred.                                                  |
| `on_call_state_updated`       | `transport, state`               | The call state changed: `"ringing"`, `"established"`, or `"closed"`.         |
| `on_dialin_ready`             | `transport, aor`                 | The account registered; `aor` is the registered address-of-record.           |
| `on_dialin_connected`         | `transport, data`                | An inbound call was established.                                             |
| `on_dialin_stopped`           | `transport, data`                | An inbound call ended. `data["reason"]` is `"transferred"` after a transfer. |
| `on_dialin_error`             | `transport, data`                | An inbound call could not be answered.                                       |
| `on_dialin_warning`           | `transport, data`                | An audio warning on an inbound call.                                         |
| `on_dialout_connected`        | `transport, data`                | An outbound call is ringing at the far end.                                  |
| `on_dialout_answered`         | `transport, data`                | An outbound call was answered.                                               |
| `on_dialout_stopped`          | `transport, data`                | An outbound call ended, including one that closed before it connected.       |
| `on_dialout_error`            | `transport, data`                | An outbound call failed.                                                     |
| `on_dialout_warning`          | `transport, data`                | An audio warning on an outbound call.                                        |
| `on_dtmf_event`               | `transport, data`                | A DTMF digit was received. `data["tone"]` is the digit.                      |
| `on_first_participant_joined` | `transport, participant`         | The first call of this transport was established.                            |
| `on_participant_joined`       | `transport, participant`         | A call was established.                                                      |
| `on_client_connected`         | `transport, participant`         | A call was established; a `ClientConnectedFrame` is pushed downstream.       |
| `on_participant_left`         | `transport, participant, reason` | A call ended; `reason` is `"leftCall"`.                                      |
| `on_client_disconnected`      | `transport, participant`         | An established call ended.                                                   |
| `on_participant_updated`      | `transport, participant`         | The peer put the call on hold or resumed it, or video was renegotiated.      |
| `on_call_quality_stats`       | `transport, stats`               | Final call quality statistics, fired when a call closes.                     |

Dial event `data` dicts carry `sessionId` and `sipCallId`. Dial-in data adds `sipFrom`, `sipTo`, and `sipHeaders`; dial-out data adds `origin` and `destination`; error and warning data carries `errorMsg`.

```python
@transport.event_handler("on_dialout_stopped")
async def on_dialout_stopped(transport, data):
    print(f"Call {data['sessionId']} ended: {data['reason']}")
```

### SIPConnection Events

`SIPConnection` has its own event handlers, registered with `connection.add_event_handler(name, handler)`. Most bots use the transport's events above; the connection's `incoming` event is how a bot with `auto_answer=False` answers or declines a call.

| Event              | Arguments                                    | Description                                                      |
| ------------------ | -------------------------------------------- | ---------------------------------------------------------------- |
| `connected`        | `connection`                                 | The connection is up.                                            |
| `disconnected`     | `connection`                                 | The connection closed.                                           |
| `registered`       | `connection, aor`                            | The account registered.                                          |
| `incoming`         | `connection, data`                           | An inbound call arrived and is ringing.                          |
| `call_progress`    | `connection, data`                           | A call is ringing.                                               |
| `call_established` | `connection, data`                           | A call was established.                                          |
| `call_closed`      | `connection, data`                           | A call closed.                                                   |
| `call_failed`      | `connection, data`                           | An outbound call failed.                                         |
| `dtmf`             | `connection, digit_event, session_id`        | A DTMF digit was received.                                       |
| `remote_hold`      | `connection, data`                           | The peer put the call on hold or resumed it.                     |
| `renegotiated`     | `connection, data`                           | Media was renegotiated mid-call (video added, removed, changed). |
| `audio_warning`    | `connection, warning, direction, session_id` | An audio warning on a call.                                      |
| `media_restarted`  | `connection, kind`                           | A media stream restarted.                                        |
