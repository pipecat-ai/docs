## Overview

`LiveKitTransport` provides real-time audio and video communication capabilities using LiveKit's open-source WebRTC platform. It supports bidirectional audio streaming, video output, data messaging, participant management, and room event handling for conversational AI applications with the flexibility of self-hosted or cloud infrastructure.

## Installation

To use LiveKitTransport, install the required dependencies:

```bash
uv add "pipecat-ai[livekit]"
```

## Prerequisites

### LiveKit Setup

Before using LiveKitTransport, you need:

1. **LiveKit Server**: Set up self-hosted or use [LiveKit Cloud](https://cloud.livekit.io/)
2. **API Credentials**: Generate API key and secret from your LiveKit project
3. **Room Management**: Create rooms using LiveKit API or SDK
4. **Access Tokens**: Generate JWT tokens for room authentication

### Required Environment Variables

- `LIVEKIT_API_KEY`: Your LiveKit API key for authentication
- `LIVEKIT_API_SECRET`: Your LiveKit API secret for token generation
- `LIVEKIT_URL`: Your LiveKit server URL (wss://your-domain.livekit.cloud)

### Key Features

- **Open Source**: Self-hosted or cloud-hosted WebRTC infrastructure
- **Multi-participant Support**: Handle multiple participants in rooms
- **Data Channels**: Real-time messaging alongside audio streams
- **Room Management**: Dynamic participant and room lifecycle management
- **Flexible Deployment**: Self-hosted or managed cloud options

</ParamField>

### LiveKitParams

Video output publishes a single `"pipecat-video"` camera track when `video_out_enabled` is set (mirroring how audio output always publishes one `"pipecat-audio"` microphone track). The track is sized using `video_out_width`/`video_out_height` and publishes each frame in its own `format`, which must be `"RGB"`, `"RGBA"`, `"BGRA"` or `"ARGB"`; frames in other formats are dropped and an error is logged. `video_out_framerate` governs how often frames are drawn. Per-destination video routing (multiple named output tracks, as supported by Daily's `camera_out_enabled`/`register_video_destination`) is not yet implemented for LiveKit.

`video_out_codec` selects the published video codec (`"VP8"`, `"H264"`, `"VP9"`, `"AV1"` or `"H265"`); LiveKit picks one when unset.

<ParamField path="audio_in_user_tracks" type="bool" default="True">
  Receive each participant's audio as its own stream of `UserAudioRawFrame`s
  tagged with their identity. All of these streams enter the pipeline through
  the one input transport, so a pipeline that runs a single STT and VAD should
  only receive one of them. When `False`, the participants' audio is mixed into
  a single real-time stream of `InputAudioRawFrame`s.
</ParamField>

<ParamField path="audio_out_queue_size_ms" type="int" default="1000">
  Buffer size of the outgoing audio source, in milliseconds. LiveKit's default
  is 1000 ms.
</ParamField>

<ParamField path="video_out_max_bitrate" type="int | None" default="None">
  Maximum bitrate of the published video track, in bits per second. When set,
  `video_out_framerate` is also sent as the track's maximum framerate. LiveKit
  chooses the encoding from the track resolution when unset.
</ParamField>

### Video input

With `video_in_enabled`, a participant's camera (`"camera"`) and screen share (`"screenVideo"`) are received separately, and each `UserImageRawFrame` carries its source in `transport_source`. Without `video_in_sources`, every frame of every video track is passed on. With it, only the listed sources are, each at its own framerate (see [TransportParams](/api-reference/server/services/transport/transport-params)).

A `UserImageRequestFrame` is answered with the next frame of the requested source, so image-request tools such as `fetch_user_image` work with LiveKit. A request for a source the participant isn't sending, for a source not listed in `video_in_sources` (when it is set) and not captured with `capture_participant_video()`, or one still waiting when the participant stops sending it or leaves, completes with an error result. Without `video_in_enabled=True`, no frames are received, so a request waits until the participant stops sending the source or leaves.

`capture_participant_video(participant_id, framerate=30, video_source="camera", *, on_request_only=False)` is a coroutine that captures a source at a framerate and takes precedence over `video_in_sources`. A `framerate` of `None` passes on every frame, and `on_request_only=True` passes on frames only to answer image requests. Get the `participant_id` with `transport.get_client_id(client)`. Passing `framerate=0` is deprecated since 1.13.0; use `on_request_only=True`.

## Usage

LiveKitTransport connects your Pipecat bot to LiveKit rooms where it can communicate with participants through audio and data channels. The transport handles room joining, participant events, and media streaming automatically.

See the [complete example](https://github.com/pipecat-ai/pipecat/blob/main/examples/transports/transports-livekit.py) for a full implementation including:

- LiveKit room creation and token generation
- Transport configuration with participant management
- Pipeline integration with audio processing
- Event handling for room lifecycle management

## Event Handlers

LiveKitTransport provides event handlers for room lifecycle, participant management, and media track events. Register handlers using the `@event_handler` decorator on the transport instance.

### Events Summary

| Event                         | Description                         |
| ----------------------------- | ----------------------------------- |
| `on_connected`                | Connected to the room               |
| `on_disconnected`             | Disconnected from the room          |
| `on_before_disconnect`        | About to disconnect (sync)          |
| `on_first_participant_joined` | First participant joined            |
| `on_participant_connected`    | A participant connected             |
| `on_participant_disconnected` | A participant disconnected          |
| `on_participant_left`         | A participant left                  |
| `on_client_connected`         | A participant connected (alias)     |
| `on_client_disconnected`      | A participant disconnected (alias)  |
| `on_audio_track_subscribed`   | Audio track subscribed              |
| `on_audio_track_unsubscribed` | Audio track unsubscribed            |
| `on_video_track_subscribed`   | Video track subscribed              |
| `on_video_track_unsubscribed` | Video track unsubscribed            |
| `on_app_message`              | JSON app message received           |
| `on_data_received`            | Data message received               |
| `on_active_speaker_changed`   | Loudest speaker in the room changed |
| `on_dtmf_event`               | SIP DTMF tone received (telephony)  |

### Room Lifecycle

#### on_connected

Fired when the bot successfully connects to the LiveKit room.

```python
@transport.event_handler("on_connected")
async def on_connected(transport):
    print("Connected to LiveKit room")
```

**Parameters:**

| Parameter   | Type               | Description            |
| ----------- | ------------------ | ---------------------- |
| `transport` | `LiveKitTransport` | The transport instance |

#### on_disconnected

Fired when the bot disconnects from the room.

```python
@transport.event_handler("on_disconnected")
async def on_disconnected(transport):
    print("Disconnected from LiveKit room")
```

**Parameters:**

| Parameter   | Type               | Description            |
| ----------- | ------------------ | ---------------------- |
| `transport` | `LiveKitTransport` | The transport instance |

#### on_before_disconnect

Fired synchronously just before the bot disconnects from the room. Use this for cleanup that must happen before disconnection.

```python
@transport.event_handler("on_before_disconnect")
async def on_before_disconnect(transport):
    print("About to disconnect...")
```

**Parameters:**

| Parameter   | Type               | Description            |
| ----------- | ------------------ | ---------------------- |
| `transport` | `LiveKitTransport` | The transport instance |

<Note>
  This is a **synchronous** event — the bot will not disconnect until all
  handlers complete. Keep handlers fast.
</Note>

### Participants

<Note>
  Participant IDs in LiveKitTransport are LiveKit identities (the `identity`
  field set when creating access tokens), not session IDs. Methods like
  `get_participants()`, `get_participant_metadata()`, `mute_participant()`, and
  `unmute_participant()` all use identities, as do all participant-related event
  handlers. `mute_participant()` and `unmute_participant()` stop and resume the
  bot receiving that participant's audio; they don't mute the participant for
  anyone else in the room.
</Note>

#### on_first_participant_joined

Fired when the first participant (other than the bot) joins the room, or is already in it when the bot connects. It fires again for the next participant after the room empties. This is commonly used to start the conversation.

```python
@transport.event_handler("on_first_participant_joined")
async def on_first_participant_joined(transport, participant_id):
    await worker.queue_frame(TTSSpeakFrame("Hello! How can I help you today?"))
```

**Parameters:**

| Parameter        | Type               | Description                        |
| ---------------- | ------------------ | ---------------------------------- |
| `transport`      | `LiveKitTransport` | The transport instance             |
| `participant_id` | `str`              | The participant's LiveKit identity |

#### on_participant_connected

Fired when a participant connects to the room, and for each participant already in the room when the bot connects.

```python
@transport.event_handler("on_participant_connected")
async def on_participant_connected(transport, participant_id):
    print(f"Participant connected: {participant_id}")
```

**Parameters:**

| Parameter        | Type               | Description                        |
| ---------------- | ------------------ | ---------------------------------- |
| `transport`      | `LiveKitTransport` | The transport instance             |
| `participant_id` | `str`              | The participant's LiveKit identity |

#### on_participant_disconnected

Fired when a participant disconnects from the room.

```python
@transport.event_handler("on_participant_disconnected")
async def on_participant_disconnected(transport, participant_id):
    print(f"Participant disconnected: {participant_id}")
```

**Parameters:**

| Parameter        | Type               | Description                        |
| ---------------- | ------------------ | ---------------------------------- |
| `transport`      | `LiveKitTransport` | The transport instance             |
| `participant_id` | `str`              | The participant's LiveKit identity |

<Note>
  When a participant disconnects, both `on_participant_disconnected` and
  `on_participant_left` fire. The `on_participant_left` event includes a
  `"disconnected"` reason for compatibility with other transports.
</Note>

#### on_participant_left

Fired when a participant leaves the room. This is a transport-agnostic event that fires alongside `on_participant_disconnected`.

```python
@transport.event_handler("on_participant_left")
async def on_participant_left(transport, participant_id, reason):
    print(f"Participant left: {participant_id} ({reason})")
```

**Parameters:**

| Parameter        | Type               | Description                                 |
| ---------------- | ------------------ | ------------------------------------------- |
| `transport`      | `LiveKitTransport` | The transport instance                      |
| `participant_id` | `str`              | The participant's LiveKit identity          |
| `reason`         | `str`              | Reason for leaving (e.g., `"disconnected"`) |

#### on_client_connected / on_client_disconnected

Transport-agnostic aliases that fire alongside `on_participant_connected` and `on_participant_disconnected` respectively, for compatibility with other transports. The handler receives the participant as a dict, with the LiveKit identity under `"id"`.

```python
@transport.event_handler("on_client_connected")
async def on_client_connected(transport, client):
    print(f"Client connected: {client['id']}")
```

### Media Tracks

Track subscription events fire when audio or video tracks from participants are subscribed or unsubscribed. All receive `(transport, participant_id)`, where `participant_id` is the participant's LiveKit identity.

| Event                         | Description                                     |
| ----------------------------- | ----------------------------------------------- |
| `on_audio_track_subscribed`   | Audio track from a participant was subscribed   |
| `on_audio_track_unsubscribed` | Audio track from a participant was unsubscribed |
| `on_video_track_subscribed`   | Video track from a participant was subscribed   |
| `on_video_track_unsubscribed` | Video track from a participant was unsubscribed |

```python
@transport.event_handler("on_audio_track_subscribed")
async def on_audio_track_subscribed(transport, participant_id):
    print(f"Audio track subscribed for: {participant_id}")
```

### Messaging

#### on_app_message

Fired when a data channel message parses as a JSON object. `on_data_received` fires for the same packet with the raw bytes.

```python
@transport.event_handler("on_app_message")
async def on_app_message(transport, message, participant_id):
    print(f"Message from {participant_id}: {message}")
```

**Parameters:**

| Parameter        | Type                | Description                                                          |
| ---------------- | ------------------- | -------------------------------------------------------------------- |
| `transport`      | `LiveKitTransport`  | The transport instance                                               |
| `message`        | `dict`              | The parsed JSON message                                              |
| `participant_id` | `str` &#124; `None` | The sender's LiveKit identity, or `None` for server SDK-sent packets |

#### on_data_received

Fired when data is received through LiveKit's data channel. The sender is `None` for packets sent by a server SDK, which LiveKit delivers unattributed.

```python
@transport.event_handler("on_data_received")
async def on_data_received(transport, data, participant_id):
    if participant_id:
        print(f"Data from {participant_id}: {data.decode()}")
    else:
        print(f"Data from server SDK: {data.decode()}")
```

**Parameters:**

| Parameter        | Type                | Description                                                          |
| ---------------- | ------------------- | -------------------------------------------------------------------- |
| `transport`      | `LiveKitTransport`  | The transport instance                                               |
| `data`           | `bytes`             | The raw data received                                                |
| `participant_id` | `str` &#124; `None` | The sender's LiveKit identity, or `None` for server SDK-sent packets |

### Active Speaker

#### on_active_speaker_changed

Fired when the room's loudest speaker changes. The bot can be the active speaker while it talks.

```python
@transport.event_handler("on_active_speaker_changed")
async def on_active_speaker_changed(transport, participant):
    print(f"Active speaker: {participant['id']}")
```

**Parameters:**

| Parameter     | Type               | Description                                   |
| ------------- | ------------------ | --------------------------------------------- |
| `transport`   | `LiveKitTransport` | The transport instance                        |
| `participant` | `dict`             | Contains `id`, the speaker's LiveKit identity |

### Telephony

#### on_dtmf_event

Fired when a SIP DTMF tone is received from a participant (available when using LiveKit with SIP/PSTN calls). The transport automatically pushes an `InputDTMFFrame` downstream, so `DTMFAggregator` works with LiveKit telephony.

```python
@transport.event_handler("on_dtmf_event")
async def on_dtmf_event(transport, data):
    digit = data.get("digit")
    print(f"DTMF digit received: {digit}")
```

**Parameters:**

| Parameter   | Type               | Description                                                                                                                                                |
| ----------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `transport` | `LiveKitTransport` | The transport instance                                                                                                                                     |
| `data`      | `dict`             | DTMF data with keys `tone`/`digit` (str), `code` (int), and `participant_id` (str, the LiveKit identity, or `None` when the packet carries no participant) |

<Note>
  The transport pushes `InputDTMFFrame` automatically, so you only need this
  handler for custom DTMF logic. Use `DTMFAggregator` to collect digits into
  sequences.
</Note>
