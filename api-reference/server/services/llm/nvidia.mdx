## Overview

`NvidiaLLMService` provides access to NVIDIA's NIM language models through an OpenAI-compatible interface. It inherits from `OpenAILLMService` and supports streaming responses, function calling, and context management.

## Installation

To use NVIDIA NIM services, install the required dependencies:

```bash
uv add "pipecat-ai[nvidia]"
```

## Prerequisites

### NVIDIA NIM Setup

Before using NVIDIA NIM LLM services, you need:

1. **NVIDIA Developer Account** (cloud endpoint only): Sign up at [NVIDIA Developer Portal](https://developer.nvidia.com/)
2. **API Key** (cloud endpoint only): Generate an NVIDIA API key for NIM cloud services
3. **Model Selection**: Choose from available NIM-hosted models
4. **Local NIM Setup** (optional): For local deployments, configure NIM on-premises and set the `base_url` to your local endpoint

### Environment Variables

- `NVIDIA_API_KEY`: Your NVIDIA API key for authentication (required for the cloud endpoint)

## Configuration

<ParamField path="api_key" type="str | None" default="None">
  NVIDIA API key for authentication. Required when using the cloud endpoint
  (`https://integrate.api.nvidia.com/v1`). Can be omitted for a local NIM
  deployment that doesn't check keys.
</ParamField>

<ParamField
  path="base_url"
  type="str"
  default="https://integrate.api.nvidia.com/v1"
>
  Base URL for NIM API endpoint. Defaults to NVIDIA's cloud endpoint. For local
  deployments, pass the local address (e.g., `http://localhost:8000/v1`).
</ParamField>

<ParamField path="model" type="str" default="None" deprecated>
  _Deprecated since 0.0.105, removed in 2.0.0._ Use
  `settings=NvidiaLLMService.Settings(model=...)` instead.
</ParamField>

<ParamField path="settings" type="NvidiaLLMService.Settings" default="None">
  Runtime-configurable settings. See [Settings](#settings) below.
</ParamField>

The constructor also accepts `default_headers`, `service_tier`,
`retry_on_timeout`, and `retry_timeout_secs`, as described for
[`OpenAILLMService`](/api-reference/server/services/llm/openai#configuration).

### Settings

Runtime-configurable settings passed via the `settings` constructor argument using `NvidiaLLMService.Settings(...)`. These can be updated mid-conversation with `LLMUpdateSettingsFrame`. See [Service Settings](/pipecat/fundamentals/service-settings) for details.

This service uses the same settings as `OpenAILLMService`. See [OpenAI LLM Settings](/api-reference/server/services/llm/openai#settings) for the full parameter reference.

The default model is `"nvidia/nemotron-3-super-120b-a12b"`.

## Usage

### Basic Setup

```python
import os
from pipecat.services.nvidia.llm import NvidiaLLMService

llm = NvidiaLLMService(
    api_key=os.getenv("NVIDIA_API_KEY"),
    settings=NvidiaLLMService.Settings(
        model="nvidia/nemotron-3-super-120b-a12b",
    ),
)
```

### With Custom Settings

```python
from pipecat.services.nvidia.llm import NvidiaLLMService

llm = NvidiaLLMService(
    api_key=os.getenv("NVIDIA_API_KEY"),
    settings=NvidiaLLMService.Settings(
        model="nvidia/nemotron-3-super-120b-a12b",
        temperature=0.7,
        top_p=0.9,
        max_completion_tokens=1024,
    ),
)
```

## Notes

- **Token reporting**: Token usage is reported once per completion at the end of each request.
- **Cloud vs. local deployment**: NIM supports both cloud-hosted and on-premises deployments. For on-premises, override the `base_url` to point to your local NIM endpoint.
- **Reasoning content**: The service automatically detects and filters reasoning content from model responses, emitting it as `LLMThought*Frame` objects. This applies to:
  - Models with API-level reasoning separation (e.g., Nemotron Nano models) that include a `reasoning_content` or `reasoning` field
  - Models that begin their response with a `<think>...</think>` block (e.g., DeepSeek-R1, some Nemotron models)

  Reasoning frames are accessible to observers and logging but are not sent to TTS, keeping the spoken output clean while preserving visibility into the model's thought process.
