## Overview

`FloeLLMService` provides an OpenAI-compatible interface for running LLMs
through [Floe](https://floelabs.xyz) — a unified billing ledger for voice AI
where one key powers the LLM, STT, and TTS legs of an agent, metered per call
and bounded by pre-call spend caps. It extends Pipecat's `OpenAILLMService`, so
streaming responses, function calling, usage/TTFB metrics, and OpenTelemetry
tracing all work unchanged.

**BYOK-first.** Pass `provider_key=` with your own vendor key (e.g. your OpenAI
key) and Floe routes the call on your key, billing only its service fee while
still metering the call and enforcing your spend caps. Omit it to go **keyless**
and let Floe manage the provider keys.

## Installation

This is a community-maintained package distributed separately from `pipecat-ai`:

```bash
uv add pipecat-floe
```

## Prerequisites

### Floe Account Setup

Before using the Floe LLM service, you need:

1. **Floe Account**: Sign up at the [Floe dashboard](https://dev-dashboard.floelabs.xyz)
2. **API Key**: Create an agent key from your dashboard. New keys come with
   welcome credit that covers the first calls.

### Required Environment Variables

- `FLOE_API_KEY`: Your Floe agent key for authentication

## Configuration

<ParamField path="api_key" type="str" default="None">
  Floe agent key. Falls back to the `FLOE_API_KEY` environment variable if not
  provided. Raises `ValueError` if neither is set.
</ParamField>

<ParamField path="model" type="str" default="openai/gpt-4o-mini">
  Fully qualified `provider/model` identifier (for example
  `"openai/gpt-4o-mini"` or `"anthropic/claude-sonnet-4-6"`). A bare model name
  is rejected by Floe.
</ParamField>

<ParamField
  path="base_url"
  type="str"
  default="https://credit-api.floelabs.xyz/v1"
>
  Floe OpenAI-compatible base URL.
</ParamField>

<ParamField path="task_id" type="str" default="None">
  Optional Floe task ID sent as the `X-Floe-Task-Id` header on every request, so
  a per-task budget can bound one conversation.
</ParamField>

<ParamField path="provider_key" type="str" default="None">
  **BYOK.** Your upstream vendor key (for example your OpenAI key), sent as the
  `X-Floe-Provider-Key` header. Floe routes the call on your key and bills only
  its service fee, while still metering the call and enforcing your spend caps.
  Omit for the keyless path (Floe-managed provider keys).
</ParamField>

<ParamField path="kwargs">
  Additional keyword arguments passed through to the underlying
  `OpenAILLMService`.
</ParamField>

## Usage

```python
import os
from pipecat_floe import FloeLLMService, FloeSTTService, FloeTTSService
from pipecat.pipeline.pipeline import Pipeline

# One Floe key powers all three legs, on a single budget.
# BYOK — bring your own vendor key; Floe meters + caps and bills only its fee.
oai = os.environ["OPENAI_API_KEY"]
stt = FloeSTTService()                                              # keyless streaming STT
llm = FloeLLMService(model="openai/gpt-4o-mini", provider_key=oai)  # BYOK
tts = FloeTTSService(model="openai/tts-1", voice="alloy", provider_key=oai)

# ...or omit provider_key to run keyless (Floe manages the vendor keys).
pipeline = Pipeline([stt, llm, tts])
```

See the [source repository](https://github.com/Floe-Labs/pipecat-floe) for a
complete runnable example wiring a WebSocket transport → STT → LLM → TTS.
