The `eval` command group runs [Pipecat eval scenarios](/pipecat/evals/overview) against an agent deployed on Pipecat Cloud. For concepts, scenario examples, and the equivalent API calls, see the [Evals guide](/pipecat-cloud/guides/evals).

<Warning>
  A synthetic run starts real sessions of your agent, and the agent calls its
  real tools. Use test credentials or a staging deployment.
</Warning>

Creating a run for an agent in a region without hosted evals is refused by the API. When the API answers that evals are not available, a command fails with `Evals aren't available yet.`

## run

Create synthetic eval runs from a scenario file. With `--session`, judge that finished session instead.

**Usage:**

```shell
pipecat cloud eval run [ARGS] [OPTIONS]
```

**Arguments:**

<ParamField path="agent" type="string" required>
  Name of the deployed agent to run against.
</ParamField>

<ParamField path="scenario_file" type="path" required>
  The scenario YAML file to run. Each selected scenario creates a separate run.
</ParamField>

**Options:**

<ParamField path="--scenario" type="string">
  Name of a scenario in the file. Repeat to select several, in the order named.
  Each name runs once. When omitted, runs every scenario in file order.
</ParamField>

<ParamField path="--session" type="string">
  ID of an ended session of the agent. The run judges that session's
  conversation by the scenario's `success:` and `metrics:`. Exactly one scenario
  must be selected; use `--scenario` when the file holds several.
</ParamField>

<ParamField path="--param" type="string">
  A synthetic run's setting as `KEY=VALUE`, where the value is a number. Repeat
  the option for several. The settings are `connectTimeoutSeconds`,
  `botReadyTimeoutSeconds` and `defaultTimeoutMs`. Not allowed with `--session`.
</ParamField>

<ParamField path="--deadline" type="integer">
  Seconds each run may take from its creation. The API sets the bounds: see
  [Limits](/pipecat-cloud/guides/evals#limits).
</ParamField>

<ParamField path="--root" type="path">
  Directory the scenario's included files are read from, and may not leave.
  Defaults to the scenario file's directory. The scenario file must be inside
  it. A scenario that includes `../` files needs `--root` set to the directory
  above, as in the [guide](/pipecat-cloud/guides/evals#included-files).
</ParamField>

<ParamField path="--wait / --no-wait" type="boolean" default="true">
  Wait for the runs to end, then print their results and exit with the combined
  verdict's code. With `--no-wait`, print the accepted runs and return.
</ParamField>

<ParamField path="--verbose / -v" type="boolean" default="false">
  Print each run's conversation and the checks or judgments that decided it
  after it ends. Has no effect on JSON output.
</ParamField>

<ParamField path="--organization / -o" type="string">
  Organization to run in. If not provided, uses the current organization from
  your configuration.
</ParamField>

<ParamField path="--json" type="boolean" default="false">
  Print the result as JSON on stdout. Alias for the global [`--output
  json`](/api-reference/cli/cloud/output).
</ParamField>

Runs are submitted separately: an accepted run continues even if another request fails. The CLI does not retry creation requests or automatically cancel accepted runs.

```shell
pipecat cloud eval run my-agent scenarios/greeting.yaml --scenario capital_question
```

### JSON Output

For one selected scenario, `run --json` prints the acknowledged run as one object. For several selected scenarios, normal completion, `--no-wait` and Ctrl-C print a list in selection order. Acknowledged runs keep their API fields, including `id`; scenarios without an acknowledged run use these fields:

| Field                          | Meaning                                                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scenarioPath`, `scenarioName` | The selected scenario.                                                                                                                                                                |
| `submissionStatus`             | `error` for a returned creation failure; `unknown` for an interrupted creation request that may have reached the API; `not_submitted` for a scenario whose request was not attempted. |
| `error`                        | Original error details, when present. Fields such as `error`, `code` or `reason` depend on the API response.                                                                          |

These entries describe submission, not a server run's terminal `status`. An interruption during submission preserves known run IDs, marks the in-flight request `unknown` and leaves the remaining scenarios `not_submitted`. An interruption while waiting preserves the latest known runs and any submission failures. For a single-scenario creation interrupted before acknowledgment, stdout is an error object with code `CLI-INTERRUPTED`; a run may exist. Read stdout even when the command exits nonzero.

### The files a run sends

A run sends the scenario file and every file it pulls in with `!include`, keyed by path relative to `--root`. Includes resolve relative to the file that names them, and nothing else in the directory is sent. Before any request, the CLI refuses a bundle that breaks one of these rules, and names the file:

- The files total at most 256 KiB of UTF-8 text.
- An include stays inside the root. Absolute paths and `..` that leave it are refused, and so is a symlink that points outside the root.
- Hidden files and folders (any path part starting with `.`) are refused, and so are files named `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `id_rsa*`, `id_dsa*`, `id_ecdsa*` or `id_ed25519*`. A symlink to such a file is refused too.
- Files must be UTF-8 text with no NUL characters.
- Includes nest at most 8 deep and don't include themselves. One load of the scenario reads at most 200 files, 256 KiB and 20,000 values, and an include counts each time it is named.

### Exit codes

When waiting, the exit code combines every selected run's outcome. If several codes apply, the priority is `3`, then `1`, then `2`, then `0`:

| Code  | Meaning                                                             |
| ----- | ------------------------------------------------------------------- |
| `0`   | Every verdict is `passed` or `skipped`.                             |
| `1`   | At least one verdict is `failed`.                                   |
| `2`   | At least one run ended without a verdict, a cancelled run included. |
| `3`   | An API error, a usage error, or a bundle that can't be sent.        |
| `130` | You pressed Ctrl-C.                                                 |

With `--no-wait`, `0` means the API accepted every request. Usage errors exit `3`, not the `2` that shells usually use, so that `2` always means a run with no verdict.

Pressing Ctrl-C stops submission or waiting and exits `130`; it does not cancel accepted runs. A creation request in flight may have reached the API. Use `pipecat cloud eval list AGENT` to find it, [`status`](#status) to check a known run ID, or [`cancel`](#cancel) to request cancellation.

## status

Show a run. With `--wait`, wait for it to end.

**Usage:**

```shell
pipecat cloud eval status [ARGS] [OPTIONS]
```

**Arguments:**

<ParamField path="run_id" type="string" required>
  ID of the run.
</ParamField>

**Options:**

<ParamField path="--agent / -a" type="string" required>
  Name of the agent the run is on.
</ParamField>

<ParamField path="--wait" type="boolean" default="false">
  Wait for the run to end, then print the result and exit with the verdict's
  code. See [exit codes](#exit-codes).
</ParamField>

<ParamField path="--verbose / -v" type="boolean" default="false">
  Print the run's conversation and the checks or judgments that decided it after
  it ends. Has no effect on JSON output.
</ParamField>

<ParamField path="--organization / -o" type="string">
  Organization to query. If not provided, uses the current organization from
  your configuration.
</ParamField>

<ParamField path="--json" type="boolean" default="false">
  Print the run as JSON on stdout.
</ParamField>

A finished run prints its verdict, reason, failures with their turns, and metrics.

## list

List an agent's eval runs, newest first.

**Usage:**

```shell
pipecat cloud eval list [ARGS] [OPTIONS]
```

**Arguments:**

<ParamField path="agent" type="string" required>
  Name of the agent.
</ParamField>

**Options:**

<ParamField path="--limit / -n" type="integer" default="10">
  How many runs to show, from 1 to 200.
</ParamField>

<ParamField path="--offset" type="integer" default="0">
  How many of the newest runs to skip. When more runs remain, the command prints
  the `--offset` for the next page.
</ParamField>

<ParamField path="--organization / -o" type="string">
  Organization to query. If not provided, uses the current organization from
  your configuration.
</ParamField>

<ParamField path="--json" type="boolean" default="false">
  Print the page as JSON on stdout.
</ParamField>

## cancel

Request cancellation of a run. The command succeeds when the request is recorded or the run is already cancelled; it may still be `starting` or `running`. No further cancel request is needed. You can optionally use [`status`](#status) to check the outcome. Stopping is best effort; the result reason describes any unconfirmed stop. Cancellation does not undo usage already incurred by an agent session. A run that finished another way is an error.

**Usage:**

```shell
pipecat cloud eval cancel [ARGS] [OPTIONS]
```

**Arguments:**

<ParamField path="run_id" type="string" required>
  ID of the run.
</ParamField>

**Options:**

<ParamField path="--agent / -a" type="string" required>
  Name of the agent the run is on.
</ParamField>

<ParamField path="--organization / -o" type="string">
  Organization to run in. If not provided, uses the current organization from
  your configuration.
</ParamField>

<ParamField path="--json" type="boolean" default="false">
  Print the run as JSON on stdout.
</ParamField>
