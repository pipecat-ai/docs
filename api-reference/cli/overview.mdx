## Requirements

- Python 3.11 or later

## Installation

The CLI ships with `pipecat-ai` as the optional `cli` extra. Install it globally with [uv](https://docs.astral.sh/uv/):

```bash
uv tool install "pipecat-ai[cli]"
```

Verify installation:

```bash
pipecat --version
```

<Tip>All commands can use either `pipecat` or the shorter `pc` alias.</Tip>

This gives you `pipecat init`, `pipecat eval`, and `pipecat context-hub`. The Context Hub bundles a local retrieval stack, so it accounts for most of the extra's install size. Deploy commands come from a separate package, co-installed with `--with`:

```bash
uv tool install "pipecat-ai[cli]" --with pipecatcloud
```

<Warning>
  `--with` replaces the tool environment rather than adding to it, so every run
  must name every plugin you want.
</Warning>

`pipecat cloud` still appears in `pipecat --help` without that package, and prints how to enable itself when run.

## Commands

- **[`pipecat init`](/api-reference/cli/init)** - Initialize and scaffold a new Pipecat project, the single entry point for new projects (built in)
- **[`pipecat eval`](/api-reference/cli/eval)** - Run behavioral evals against your agents
- **[`pipecat context-hub`](/api-reference/cli/context-hub)** - Query the Pipecat Context Hub and register it with your coding agent (built in)
- **[`pipecat cloud`](/api-reference/cli/cloud/auth)** - Deploy and manage bots on Pipecat Cloud (requires `pipecatcloud`)

## Output modes and exit codes

Every `pipecat cloud` command accepts a global `--output` option that controls how results are rendered. Place it before the subcommand:

```bash
pipecat cloud --output json agent list
```

| Mode    | Behavior                                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `rich`  | Interactive tables, panels, and spinners. The default when stdout is a terminal.                                                            |
| `plain` | Line-oriented output with no boxes and no truncation; listings are tab-separated. The default when stdout is piped or redirected.           |
| `json`  | One machine-readable JSON object on stdout, with all human-readable output on stderr. API errors are emitted as `{"error": ...}` on stdout. |

The mode is resolved in this order: the `--output` flag, then the `PIPECAT_OUTPUT` environment variable or the `output` key in your [CLI config file](/api-reference/cli/cloud/auth#configuration), then auto-detection. In CI, set `PIPECAT_OUTPUT` once to avoid flag-ordering concerns:

```bash
export PIPECAT_OUTPUT=plain
pipecat cloud deploy
```

Long-running operations such as deploy rollouts and cloud builds print each status transition as a timestamped line in `plain` and `json` modes, so progress is visible even when output is not a terminal.

### Exit codes

| Code | Meaning                                                                         |
| ---- | ------------------------------------------------------------------------------- |
| `0`  | Success                                                                         |
| `1`  | The command failed, or you cancelled it at a prompt                             |
| `2`  | Usage error, or a confirmation prompt was needed while stdin was not a terminal |

Commands that would show a confirmation prompt fail fast with exit code `2` when stdin is not a terminal, and name the flag that bypasses the prompt (`--yes`, `--force`, or `--skip` depending on the command). Pass that flag in scripts and pipelines.

<Note>
  Non-zero exit codes on failure require `pipecatcloud` 1.1.0 or later. Earlier
  versions exited `0` on every path, so pipelines built against them could not
  detect a failed deploy.
</Note>

## Getting Help

View help for any command:

```bash
pipecat --help

pipecat eval --help
pipecat context-hub --help
pipecat cloud --help
```
