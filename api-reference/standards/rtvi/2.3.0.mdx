## Connection Management

Starting and ending a session, and errors.

### Client sends

#### client-ready

Tells the server the client is ready, with the protocol version it speaks. The server answers with bot-ready.

Typically sent once the transport has connected.

<ParamField path="id" type="string" required>
  The message's id. An answer to it carries the same id.
</ParamField>
<ParamField path="data.version" type="string" required>
  The RTVI protocol version the client speaks, such as `2.3.0`.
</ParamField>
<ParamField path="data.about" type="AboutClientData" required>
  Information about the client. A server receiving a `client-ready` without it, or with an invalid one, still starts the session, as a client of an unknown library.

  <Expandable title="AboutClientData">
    <ParamField path="library" type="string" required>
      The RTVI library the client uses, such as `@pipecat-ai/client-js`.
    </ParamField>
    <ParamField path="library_version" type="string | null">
      The version of that library.
    </ParamField>
    <ParamField path="platform" type="string | null">
      The platform the client runs on, such as a browser or `iOS`.
    </ParamField>
    <ParamField path="platform_version" type="string | null">
      The platform's version.
    </ParamField>
    <ParamField path="platform_details" type="any">
      Anything else the client says about its platform.
    </ParamField>
  </Expandable>
</ParamField>

```json Example
{
  "label": "rtvi-ai",
  "type": "client-ready",
  "id": "msg_1",
  "data": {
    "version": "2.3.0",
    "about": {
      "library": "@pipecat-ai/client-js",
      "library_version": "1.16.0"
    }
  }
}
```

</ParamField>

### Client receives

#### bot-ready

Answers client-ready once the bot is ready to talk, with the protocol version the server speaks to this client, information about the bot, and what it can do. Its id is the client-ready's id.

`about` is the bot's own information: Pipecat's library and version, unless the application replaces it. An application shouldn't put anything sensitive in it.

<ParamField path="id" type="string" required>
  The id of the client message this answers.
</ParamField>
<ParamField path="data.version" type="string" required>
  The RTVI protocol version the bot speaks with this client.
</ParamField>
<ParamField path="data.about" type="object | null">
  Information about the bot, such as the Pipecat library and version.
</ParamField>
<ParamField path="data.capabilities" type="BotCapabilities | null">
  What the bot does in this session (media sent and received, metrics), so the client can show only the UI that applies. Added in protocol 2.2.0.

  <Expandable title="BotCapabilities">
    <ParamField path="audio_in" type="boolean | null">
      Whether the bot receives the user's audio.
    </ParamField>
    <ParamField path="audio_out" type="boolean | null">

    </ParamField>
    <ParamField path="video_in" type="boolean | null">

    </ParamField>
    <ParamField path="screen_in" type="boolean | null">

    <ParamField path="video_out" type="boolean | null">

#### error

Reports an error in the bot, such as an AI service that failed. When fatal is true, the bot can't go on and the session ends.

<ParamField path="data.error" type="string" required>
  What went wrong.
</ParamField>
<ParamField path="data.fatal" type="boolean" required>
  Whether the bot stopped because of the error.
</ParamField>

```json Example
{
  "label": "rtvi-ai",
  "type": "error",
  "data": {
    "error": "The LLM service failed",
    "fatal": false
  }
}
```

### Client receives

#### user-started-speaking

The user's turn started: the bot considers the user to be speaking. On by default; turned off by the server's `user_speaking_enabled` setting.

```json Example
{
  "label": "rtvi-ai",
  "type": "user-started-speaking"
}
```

#### user-stopped-speaking

The user's turn ended: the bot considers the user done speaking. On by default; turned off by the server's `user_speaking_enabled` setting.

```json Example
{
  "label": "rtvi-ai",
  "type": "user-stopped-speaking"
}
```

#### vad-user-started-speaking

Voice activity detection (VAD) heard the user start speaking. It reacts to any voice, sooner than user-started-speaking, which comes when the bot decides the user's turn started. Off by default; turned on by the server's `vad_user_speaking_enabled` setting.

```json Example
{
  "label": "rtvi-ai",
  "type": "vad-user-started-speaking"
}
```

#### vad-user-stopped-speaking

Voice activity detection (VAD) heard the user stop speaking. It reacts to any pause, sooner than user-stopped-speaking, which comes when the bot decides the user's turn ended. Off by default; turned on by the server's `vad_user_speaking_enabled` setting.

```json Example
{
  "label": "rtvi-ai",
  "type": "vad-user-stopped-speaking"
}
```

#### user-mute-started

The bot stopped listening to the user, for example while it says something that must not be interrupted. On by default; turned off by the server's `user_mute_enabled` setting.

The client should keep sending audio. It may show the user that their input isn't being processed.

```json Example
{
  "label": "rtvi-ai",
  "type": "user-mute-started"
}
```

#### user-mute-stopped

The client may show the user that their input is being processed again.

```json Example
{
  "label": "rtvi-ai",
  "type": "user-mute-stopped"
}
```

The bot was interrupted and stopped what it was saying. A client should drop the bot's text that hadn't been spoken yet. On by default; turned off by the server's `bot_speaking_enabled` setting.


Sent for each transcription of the user's speech; for each short acknowledgment the user says while the bot talks, which neither interrupts the bot nor reaches its LLM; and for each send-text message, with the send-text's id in `msg_id`.

<ParamField path="data.input_type" type="string" required>

<ParamField path="data.timestamp" type="string" required>

<ParamField path="data.final" type="boolean" required>

</ParamField>
<ParamField path="data.user_id" type="string | null">

#### bot-output

Text the bot says or shows, a sentence or another unit at a time, with whether it will be spoken and how much of it has been spoken. On by default; turned off by the server's `bot_output_enabled` setting.

<ParamField path="data.text" type="string" required>
  The text.
</ParamField>
<ParamField path="data.output_type" type="string" required>

<ParamField path="data.text_type" type="string | null">

</ParamField>
<ParamField path="data.aggregated_by" type="string | null">
  What form the text is in, always the same as `output_type`. Deprecated: Use `output_type` instead. One of `"backchannel"`, `"expression_sound"`, `"expression_pause"`, `"sentence"`, `"token"`, `"word"`.
</ParamField>
<ParamField path="data.segment_id" type="integer | null">
  Identifies the segment the text belongs to; every message about one segment, such as its spoken progress, carries the same id.
</ParamField>
<ParamField path="data.spoken" type="boolean | null">
  **(v1 only)** Whether the text has been spoken by TTS.
</ParamField>
<ParamField path="data.will_be_spoken" type="boolean | null">

</ParamField>
<ParamField path="data.spoken_status" type="string | null">

</ParamField>

  <Expandable title="SpokenProgressData">
    <ParamField path="accumulated_text" type="string" required>

    </ParamField>
    <ParamField path="remaining_text" type="string" required>

    </ParamField>
  </Expandable>
</ParamField>
<ParamField path="data.delivery" type="string[] | null">

## Server Behaviors

The rules a server follows across messages, beyond the shape of each one.

- **bot-ready-answers-client-ready**: Once the bot is ready, the server answers client-ready with a bot-ready carrying the client-ready's id. (`client-ready`, `bot-ready`)
- **bot-ready-version**: bot-ready's version is the protocol version the server speaks to the client: the server's own for a client of the same major version, and the client's own for a 1.x client. (`client-ready`, `bot-ready`)
- **client-ready-version-check**: A client-ready without a version, with a malformed one, or of a major version the server doesn't speak gets an error-response carrying its id. The session goes on, and the server still answers with bot-ready. (`client-ready`, `error-response`, `bot-ready`)
- **failed-request-gets-error-response**: A client message the server can't handle, of an unknown type or with data that doesn't match its payload, gets an error-response carrying the message's id. (`error-response`)
- **invalid-message-gets-error**: A transport message labeled "rtvi-ai" that isn't an RTVI message, such as one without an id, gets an error, since there is no id to answer. The server ignores a message without the "rtvi-ai" label. (`error`)
- **client-message-answer**: The bot answers a client-message with a server-response or an error-response carrying the client-message's id. A server-response's t is the client-message's t. (`client-message`, `server-response`, `error-response`)
- **disconnect-bot-ends-session**: disconnect-bot ends the bot's session. (`disconnect-bot`)
- **messages-turned-off**: The server sends a message that has x-rtvi-enabled-by only while the server setting it names is on. The settings are fields of Pipecat's RTVIObserverParams.
- **spoken-output-waits-for-speech**: bot-output for text the bot will speak waits for the bot to start speaking: the server sends it after bot-started-speaking, in the order the text came. (`bot-started-speaking`, `bot-output`)
- **interruption-drops-unspoken-output**: On an interruption, the server sends bot-interrupted, and never sends the bot-output it was holding for speech that the interruption cut off. (`bot-interrupted`, `bot-output`)
