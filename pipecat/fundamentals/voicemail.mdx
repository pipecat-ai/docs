description: "Automatically classify outbound calls as conversation or voicemail and respond appropriately"

## Overview

The VoicemailDetector classifies incoming communication as either live conversation or voicemail systems. This module is built primarily for voice AI bots that perform outbound calling, enabling them to respond appropriately based on whether a human answered or the call went to voicemail.

The detector is optimized for fast conversation response times, where TTS output is generated immediately but held in a gate until the classification decision is made. This ensures minimal latency for live conversations while preventing inappropriate responses to voicemail systems.

## How It Works

The VoicemailDetector collects what the other side says and asks its classifier after each transcription whether the call reached a person or a voicemail. Once the caller has been quiet for `decision_timeout` (default 1 second), the latest answer decides. The detector holds the bot's speech until the decision is made.

Key features:

- **Progressive classification** - Re-evaluates the classification as more speech is heard
- **Silence-based decision** - Waits for silence to distinguish greetings from conversations
- **TTS gating** - Holds generated audio until classification is complete
- **Event-driven** - Triggers custom handlers when voicemail is detected
- **Configurable timing** - Adjustable delays for decision and voicemail response timing

## Basic Setup

### 1. Initialize the Detector

```python
from pipecat.extensions.voicemail.voicemail_detector import VoicemailDetector
from pipecat.classifiers.jev.classifier import JevClassifier

# Create a classifier for voicemail detection
classifier = JevClassifier(api_key=os.getenv("TYPESAFE_API_KEY"))

# Initialize the detector
voicemail_detector = VoicemailDetector(
    classifier=classifier,
    voicemail_response_delay=2.0,  # Default: 2 seconds
    decision_timeout=1.0  # Default: 1 second
)
```

<Note>
  VoicemailDetector requires a classifier that implements the `BaseClassifier`
  interface. You can use `JevClassifier` for fast classification, or
  `LLMClassifier` with any LLM service that supports `run_inference()`. Realtime
  LLMs cannot back an `LLMClassifier` as they don't support one-shot inference.
</Note>

### 2. Configure the Pipeline

The VoicemailDetector requires two components in your pipeline:

- `detector()`: between STT and user context aggregator
- `gate()`: immediately after TTS service

```python
pipeline = Pipeline([
    transport.input(),
    stt,
    voicemail_detector.detector(),    # Between STT and user context aggregator
    context_aggregator.user(),
    llm,
    tts,
    voicemail_detector.gate(),        # Immediately after TTS service
    transport.output(),
    context_aggregator.assistant(),
])
```

### 3. Handle Voicemail Events

When a voicemail is detected, the `on_voicemail_detected` event is triggered. In your event handler, you have access to `processor`, which is a FrameProcessor instance, allowing you to push frames to the pipeline. For example, you may want to have the bot output a pre-canned message and then end the call.

```python
@voicemail_detector.event_handler("on_voicemail_detected")
async def handle_voicemail(processor):
    logger.info("Voicemail detected! Leaving a message...")

    # Leave a voicemail message
    await processor.push_frame(
        TTSSpeakFrame("Hello, this is Jamie calling about your appointment. Please call me back at 555-0123.")
    )

    # Optionally end the call after leaving the message. Push downstream so the
    # message finishes playing before the pipeline shuts down.
    await processor.push_frame(EndWorkerFrame(), FrameDirection.DOWNSTREAM)
```

## Detecting a Conversation

When a conversation is detected, no additional processing is required by the VoicemailDetector. Once the VoicemailDetector classifies the call as a conversation, the TTSGate will be flushed, allowing the conversation to continue.

## Configuration Options

### Using an LLM Classifier

If you prefer to use an LLM for classification instead of JevClassifier, you can use `LLMClassifier`:

```python
from pipecat.classifiers.llm.classifier import LLMClassifier
from pipecat.services.openai.llm import OpenAILLMService

llm = OpenAILLMService(api_key=os.getenv("OPENAI_API_KEY"))
classifier = LLMClassifier(llm=llm, timeout=10.0)  # Default timeout: 10 seconds

voicemail_detector = VoicemailDetector(classifier=classifier)
```

`LLMClassifier` automatically handles the classification prompt and response parsing. It supports any LLM service that implements `run_inference()`.

<Warning>
  The `llm` and `custom_system_prompt` parameters are deprecated since version
  1.12.0 and will be removed in version 2.0.0. Use the `classifier` parameter
  instead. For backward compatibility, passing `llm` will automatically wrap it
  in an `LLMClassifier`.
</Warning>

### Response Timing

The detector has two timing parameters:

**`decision_timeout`** controls how long to wait after the caller stops speaking before acting on the latest classification:

```python
voicemail_detector = VoicemailDetector(
    classifier=classifier,
    decision_timeout=1.5  # Wait 1.5 seconds instead of default 1
)
```

This ensures the detector distinguishes between a pause in a greeting (which resumes) and a person who has finished speaking and is waiting for a response.

**`voicemail_response_delay`** controls how long to wait after a voicemail verdict before triggering the `on_voicemail_detected` event:

```python
voicemail_detector = VoicemailDetector(
    classifier=classifier,
    voicemail_response_delay=3.0  # Wait 3 seconds instead of default 2
)
```

This delay ensures the voicemail greeting has finished and the recording has started before the message is left.
